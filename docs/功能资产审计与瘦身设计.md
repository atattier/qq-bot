## 二、重复能力与入口审计

### 2.1 重复的用户入口（同一能力多门）
| 能力 | 入口数 | 明细 |
|---|---|---|
| 配置修改 | **3 类** | ①设置口令 ②8 个快捷正则（MODEL/NET/ACTIVE/ENGINE/PERSONA/COMFY_ENGINE/COMFY_STYLE/COMFY_CMD）③网页工作台 |
| 文生图 | 4 | 画：/画图/来一张（口令正则）、draw_image（大脑）、cloud_draw（大脑）、网页磁贴 |
| 图生图/改图 | 5 | moss反推 / moss改： / 口语改图（动词表） / 带图点名引擎（_MENG） / draw_like_this |
| 表情类 | 3 | send_meme（大脑）/ 口令直配 / 自动配图 |

### 2.2 重复的意图判断（正则表间覆盖重叠）
- `_looks_like_edit`（改图动词表）与 `_MENG_EXPLICIT_RE`（点名引擎表）：同为"带图+文字"意图判断，词表独立演化（"图生图"漏网事故的直接根源，已打补丁）。
- 8 个配置快捷正则与 SETTINGS_RE：都往 knob_set 汇聚，但触发词独立维护。
- `_ai_route_draw`（LLM 判断）与画图口令正则：靠 draw.route 开关二选一——**两种意图判断机制并存**。

### 2.3 重复的底层实现（实际共用了，无分叉）
- 画图四入口 → 全部收敛到 `draw_submit`（阶段 0 审计确认）✅ 无需合并。
- 反推/改稿/补全 → 全部收敛到 `moss_layout.from_image/from_text/edit_draft` ✅。

### 2.4 相似但不可替代（明确保留）
| 组合 | 为什么不合并 |
|---|---|
| ComfyUI vs Moss | 本地显卡画质/档位 vs 云端速度，**两条真链路**；owner 明确两条都要 |
| 视频生成 vs 视频解析 | 生成（H3 出新视频）与解析（下载已有视频）完全不同能力 |
| 梗百科 vs 联网搜索 | 梗百科有本地 6668 词条库（毫秒级、免 API）；搜索走付费 API——互补不重复 |
| 长期记忆 vs Reflection vs 情绪 | 记账（facts）/观点（opinion）/心情（mood）三种数据三种生命周期，边界清晰 |
| 主动插话 vs 看图闲聊 vs 戳回 | 触发源不同（文本/图片/戳事件），共享 sim 频控——参数多但职责不重叠 |
| 表情制作 vs 表情抓取 vs 捏脸 | 制作（文字生成）/抓取（搜图）/捏脸（头像模板）三种产物 |
