# 人味阶段 C · 主动性层（purpose-engine）实施记录（2026-11-04）

对应研究：`docs/人味阶段研究-2026-11-03.md` §4；设计草案：`docs/人味阶段C设计草案-2026-11-04.md`。
按主人拍板的默认值与红线实现：**没有新增发送通道、没有新增定时系统、没有把逻辑塞进 bot.py**。

🔴 `purpose.enabled` 默认 **关**：关 = `idle_opener_tick` 旧逻辑（gap/chance/_idle_state）逐行不变。

## 一、机制 → 代码

独立模块 `qbot_purpose.py`（纯函数 + 状态模型；bot.py 只做最小接线）：

| 机制 | 函数 | 说明 |
|------|------|------|
| goal 模型 | `goal_from_memory` / `goal_from_observation` | 必带 source/need/confidence/value/risk/status/时间戳/**证据**；记忆卡来源需 card_id |
| observation shadow | `looks_like_observation` / `add_observation` / `observation_enabled` | 消息入口筛「计划/偏好/约定」句（排除链接/口令/隐私/过长过短）→ shadow 池；**采集与开口解耦**：目的层关着也记录，但绝不开口 |
| 调度 | `plan_next_fire` / `decide` | 每日成功上限 4、随机间隔 2.5–5h、安静时段 23:30–09:00、停机恢复最早 now+2min |
| 主人活跃闸 | `classify_owner_state` | active 拦非主人来源；idle 放行；unknown 放行但记账；连续 24h 拦截自动放行 1h 并告警 |
| 竞争与轮换 | `goal_weight` / `pick_goal` | 基础权重 + 同 need 连续降权 + 类型平衡 + 轮盘赌随机；mood 只做 0.75~1.25 软权重 |
| 多层去重 | `dedup_ok` / `text_sim` | 同 source_id / 池内 ≥0.8 / 同 need ≥0.55 / 最近发过 ≥0.55 / purpose_seen 账本 |
| 池与 TTL | `prune_pool` | 每群 ≤12、每 need ≤3、active ≤6；memory TTL 7 天、shadow TTL 3 天 |
| 提示词 | `_build_messages` | 素材归属（自己的旧事 vs 群友的事）、低置信度说成试探、risk≥0.5 先问主人、最近 3 条别重复 |
| 出口与记账 | `parse_answer` / `finish` | `[SILENT]`=主动跳过（不占成功额度、attempts+1）；发送失败不占额度、15min 重试、单 goal 3 次放弃 |
| 持久化 | `load` / `_save` | 原子写 + `.prev`；坏文件回退 `.prev`，再失败空池启动；写失败进入只读模式 |

接线（bot.py）：
- `_bind_modules()`：`qbot_purpose.bind(...)`（记忆卡候选 = `opener_candidates(limit=6)`；去重账本 = `purpose_seen`；发送仍由 bot 侧 `send_bubbles`）。
- `idle_opener_tick()`：既有硬闸（sim/idle 开关、`silent_on`、`external_brain`、时段、会话开关、`agent_working`、冷场时长）之后，`if qbot_purpose.enabled()` 接管；关闭时下面旧逻辑原样执行。
- `_last_owner_ts` 从 CONTEXT 找主人消息；`_purpose_mood_bias` 只取 `sim_bias` 做软权重；`_purpose_send` 只调 `send_bubbles`。

## 三、权威关系（落实）

```
mood 既有硬闸 → purpose 候选/调度闸 → timing 开场退避 → LLM 最终判断 → 现有发送闸
```

- 既有硬闸（sim/idle 开关、静默、外置大脑、时段、会话开关、agent_working、冷场）在 purpose 之前；
- **没有新增 `sim_bias < 0.25` 硬阈值**：`sim_bias` 只乘 0.75~1.25 的软权重（测试 ⑧ 锁死）；
- timing 只把 `opener_gap_multiplier` 当间隔乘数（测试 ⑨ 锁死），不碰消息触发路径；
- 发送只走 `_purpose_send → send_bubbles`（测试源码级断言）；
- LLM 明确 `[SILENT]` 出口；空回/占位符也按跳过处理。

## 六、未实现 / 已知限制（如实）

- `observation` 已接消息入口并与开口解耦：`purpose.enabled=False` + `purpose.observe=True`（默认）
  时只积累 shadow 数据，绝不开口；关掉 `purpose.observe` 才是真正零副作用（连记录都不做）。
  C1 仍不做自动 goal 生成（shadow 只供以后评估）。
- `owner_chat` 驱动源、私聊主动发起**未实现**（按拍板 C1 不做）。
- drives（`0.65 + 0.55×drives[need]`）暂固定 0.5，未接情绪驱动权重。
- 没有 pending 候选（研究里的 pending 50% 优先）与 goal 复活机制；rejected 状态未使用。
- 没有暂停/恢复 UI；生产上靠「设置 目的层 关」。
- owner 三态只按 CONTEXT 近 window 条判断；窗口里没有主人发言会记 unknown（正常）。

## 七、可归因实验编排（2026-11-04 主人定）

三项机制**不同时改**，否则无法判断变化来自哪一层：

1. **现在（观察期）**：`purpose.enabled=False`、`purpose.observe=True`、
   `memory.fusion="linear"` —— Bot 的开口行为与以前完全一样，只在后台积累 shadow 观察数据。
2. **C 实验**：攒够一段时间（建议 ≥3~5 天、覆盖活跃时段）后看 shadow 池：
   候选数量、句式分布、重复度；再单独开启 `purpose.enabled` 观察主动开口，
   timing 保持现状（开场退避仍生效）。
3. **D 实验**：C 的结论出来之后，才把 `memory.fusion` 切到 `rrf` 做检索质量对照；
   期间不要同时改 C 的开关。
4. 任何一步出现异常，先回滚该步的唯一开关，再定位。

## 八、修复记录（2026-11-04 主人实测）

- **同一件旧事连开多次场**（09:00 / 11:36 / 14:54 / 15:54 都在说「手机亮了一晚上」）：
  根因在 legacy `idle_opener_tick` —— 开场成功后只把**模型生成的那句话**记进去重账本，
  而 `opener_candidates` 是拿**候选原文**去比 `purpose_seen`，两边永远对不上；
  `touch_by_ids` 的复习效应还把同一条越抬越高。
  修复：把候选原文本体也 `purpose_mark`（实际措辞顺带记），新增 `_topener.py` 锁死
  「第一次用 A → 第二次必须换 B → 两条都用过不再硬凑」。
