## 0. 文档效力与阅读方式

### 0.1 本文件冻结什么

1. 目标架构，以及六个部件的**职责边界**（做什么、不做什么）。
2. `Turn`、`MediaRef`、`ToolSpec`、`ToolResult`、`Evidence` 的**数据契约**。
3. **自然语言意图**与**安全 / 权限 / 协议 / 不可逆操作硬轨**的边界。
4. 现有能力**保留清单**与**禁止误删项**。
5. `M0–M6` 的**依赖关系、验收目标、回滚原则**。
6. 当前**未决架构问题**，以及每个问题必须在哪个阶段之前拍板。

### 0.2 本文件不冻结什么

- 不冻结实现细节（类名、文件划分、函数签名可以调整，只要契约与边界不变）。
- 不冻结具体数值（超时、预算、TTL、阈值），它们属于 §8 未决问题，需在对应阶段前单独拍板。
- **不代表任何部件已经实现。** 本文中所有「目标」「应」「MUST」都是设计约束，不是现状描述。
- 不改变当前运行行为；不构成启动 `M1–M6` 的批准。

### 0.3 事实边界

- 文中标注「现状」的内容，均来自基线 `6118f8b` 的只读审计与代码/数据观察；它们是**迁移起点**，不是设计目标。
- 文中标注「目标」的内容，均为**尚未实现**的契约。
- 不得把目标架构写成已上线能力；不得把「计划合并」写成「已经可以无损合并」。
- 不得把「当前数据可重建」当作既成事实；见 §9.2 与 §8.1。

## 1. 裁决记录

本次主人裁决（2026-11-05）：

1. **接受目标架构方向**：Turn、Context Assembler、Agent Core、Tool Registry、Memory Service、Renderer。
2. **接受自然语言业务意图逐步退出正则路由**，但保留安全、管理、协议和不可逆操作硬轨。
3. **接受现有成熟能力保留**；迁移的是决策权和接口，不是重写底层能力。
4. **接受 M0–M6 作为长期迁移路线图**，但本次**不批准启动 M1–M6**。
5. **当前优先完成已在执行的 R1，不扩大当前任务范围。R3 已正式通过，不再修改。**
6. **R1–R4 处理完成后，才进入 M0。**

据此：

- 本 ADR 只做设计冻结，不改生产代码、配置、数据库或运行状态。
- `R1–R4` 是 M0 的前置门槛；本文不重新定义 R 系列任务，也不修改已通过的 R3。
- 本文不删除任何旧路由、旧表、旧缓存或能力实现；不开启 `Purpose`、`Timing`、`RRF` 等默认关闭功能。
- 本文不触碰其他会话的未提交工作。

## 2. 术语、原则与唯一性规则

### 2.1 基本术语

| 术语 | 含义 |
|---|---|
| **Turn** | 一次用户输入在系统中的不可变事实载体：文本、媒体、引用、会话、说话人、时间、任务引用 |
| **MediaRef** | 对一段媒体字节的不可变引用；字节存 MediaStore，Turn 只持有引用 |
| **Evidence** | 从记忆/历史/投影中召回的一条可溯源证据；核心只读 |
| **ToolSpec / ToolResult** | 工具能力的声明式契约与统一返回 |
| **Hard rail（硬轨）** | 在核心判断之前允许执行的确定性规则，仅限安全/权限/协议/不可逆四类 |
| **Protocol adapter（协议适配器）** | 把显式命令语法（如 `/status`）翻译成一次工具调用，不解释业务意图 |
| **Core（Agent Core）** | 唯一拥有业务意图判断权的决策循环 |
| **Projection（投影）** | 从事件日志派生出的记忆视图（facts / card / reflect / slang / expression 等） |

### 2.2 五条唯一性规则（MUST）

1. **只有 Adapter 解析外部事件。** 任何其他部件不得直接读 OneBot/NapCat 原始事件。
2. **只有 Context Assembler 组装模型消息。** 任何模块不得直接往 system / messages 追加段落。
3. **只有 Agent Core 决定业务意图与动作。** 任何正则、handler、插件不得在核心之前选择业务动作。
4. **只有 Tool Registry 执行工具。** 工具的参数校验、权限、超时、幂等、审计集中在 Registry。
5. **只有 Renderer 产生用户可见文本并发送。** 工具与 handler 返回 `user_text_hint`，不直接发消息。

> 这五条是后续所有阶段的架构验收基线。违反其一，视为该阶段未完成。

### 2.3 设计原则

- **能力保留，决策收回**：底层能力模块不做重写式迁移；迁移的是谁来决定调用它。
- **状态收敛，不假定无损**：事件日志是目标真源，但现有数据能否重建必须逐字段证明；证明不了就保留并存与只读标记。
- **硬轨只做否决或协议执行，不做业务选择**：硬轨可以拦下、可以执行 `/status`，但不能因为句子里有「画」就选择画图工具。
- **默认关闭、可回滚**：每个阶段都有独立开关；默认保持旧行为；验收通过并由主人批准后才切换。
- **不删旧路径直到新路径稳定**：M6 之前不删除旧路由、旧表、旧缓存、旧能力实现。

## 3. 目标架构与六个部件

### 3.1 关系图（设计目标）

```
                         ┌─────────────────────────────────────┐
 NapCat / OneBot 事件 ──►│ Adapter                             │
                         │ 事件 → Turn；MediaRef 入库；发送出口   │
                         └──────────────────┬──────────────────┘
                                            ▼
                         ┌─────────────────────────────────────┐
                         │ Context Assembler                   │
                         │ 唯一拼 Prompt 的地方：               │
                         │ policy + persona + recent turns      │
                         │ + memory evidence + media + skills   │
                         └──────────────────┬──────────────────┘
                                            ▼
                         ┌─────────────────────────────────────┐
                         │ Agent Core                          │
                         │ 理解 → 判断 → 决策 → 行动 → 观察      │
                         │ 唯一拥有业务意图判断权                 │
                         └───────┬───────────────────┬─────────┘
                                 │                   │
                  ┌──────────────▼──────┐   ┌────────▼─────────────┐
                  │ Tool Registry       │   │ Memory Service       │
                  │ 契约/权限/超时/审计   │   │ 召回/写入/隔离/投影   │
                  └──────────────┬──────┘   └────────┬─────────────┘
                                 │                   │
          ┌──────────────────────▼───────────────────▼─────────────┐
          │ 能力实现（只做一件事，不判意图、不拼人格、不发消息）        │
          │ draw / reverse / video / cover / jm / meme / petpet /   │
          │ scramble / voice / search / qq / skills                 │
          └──────────────────────────┬──────────────────────────────┘
                                     ▼
                         ┌─────────────────────────────────────┐
                         │ Renderer                            │
                         │ 人格表达 / 分条 / 拟人 / 审计 / 发送   │
                         └──────────────────┬──────────────────┘
                                            ▼
                                   发送 或 SILENT
                                            │
                         ┌──────────────────▼──────────────────┐
                         │ Store / commit                      │
                         │ 本轮事件 → 事件日志（目标真源）        │
                         └─────────────────────────────────────┘
```

### 3.2 六个部件的职责边界

| 部件 | 职责（MUST） | 明确不做（MUST NOT） | 输入 → 输出 |
|---|---|---|---|
| **Adapter** | 把 OneBot 事件归一成 `Turn`；把媒体落到 MediaStore；执行发送 API | 不判断意图；不拼 Prompt；不写记忆；不改写用户文本 | 原始事件 → `Turn` / 出站消息 |
| **Context Assembler** | 按预算组装 system/messages；注入 persona、policy、最近轮次、Evidence、媒体；生成工具清单 | 不调用工具；不发消息；不决定意图；不直接读写业务状态 | `Turn` → `ModelContext` |
| **Agent Core** | 理解请求；决定 `reply / ask / tool_call / refuse / silent`；循环直到收尾；处理澄清与预算 | 不直接发消息；不直接读写数据库；不绕过 Registry 调能力 | `ModelContext` → `Action[]` |
| **Tool Registry** | 注册 `ToolSpec`；校验参数；执行权限/超时/幂等/审计；统一 `ToolResult` | 不解释自然语言；不拼人格话术；不决定「该不该做」 | `ToolCall` → `ToolResult` |
| **Memory Service** | 事件日志写入；Evidence 召回；Scope 隔离；投影维护与衰减/遗忘 | 不决定说什么；不直接改 Prompt；不跨 Scope 泄漏 | 事件 / 查询 → `Evidence[]` |
| **Renderer** | 把回复意图 + 人格 + 情绪渲染成用户可见内容；分条/拟人/语音/配图；出站审计 | 不改变事实；不选择工具；不修改权限；不绕过审计 | `ReplyIntent` → 发送 / `SILENT` |

### 3.3 一次请求的目标数据流（设计目标）

```
Turn
 → Context Assembler 组装（含媒体与 Evidence）
 → Agent Core 第 1 次判断
     ├─ reply  → Renderer → 发送 → commit
     ├─ ask    → Renderer → 发送 → commit
     ├─ silent → commit
     └─ tool_call
          → Registry 校验/执行 → ToolResult
          → Core 观察结果 → 第 2 次判断 …（受预算约束）
 → 最终 reply/ask/silent → Renderer → commit
```

- 工具调用是**核心循环内部**的一步，不是核心之前的另一条消息入口。
- 同一轮可以有多次工具调用，但受 §8.5 的终止与预算规则约束。
- 任何工具都不得直接产生用户可见消息；需要说话时返回 `user_text_hint`，由 Renderer 统一表达。

### 3.4 现状对照（仅陈述事实，不代表已实现）

| 目标 | 现状（基线 `6118f8b`） |
|---|---|
| Adapter 唯一解析事件 | `parse_message` / `_scan_event` / 多个 handler 各自再读 `data["message"]` |
| Assembler 唯一拼 Prompt | `build_messages` + `ai_reply` + omni 各自追加，固定注入约 18 段 |
| Core 唯一判断意图 | 15 个 `_route_*` + 3 个内联分支在模型之前分流 |
| Registry 唯一执行工具 | 正则 handler / `_BOT_TOOLS` / MCP 三套工具面 |
| Memory Service 唯一读写 | 9 套存储 + 3 套图片缓存，各自截断/衰减/注入 |
| Renderer 唯一发送 | 多个 handler 直接发送（全文件 245 处 send 调用） |

> 上表用于迁移对照，不作为设计已完成的证据。

## 4. 数据契约（冻结 v1）

> 以下为**目标契约**。当前代码不满足这些契约；迁移阶段负责适配，不得反过来修改契约来迁就现状。

### 4.1 通用规则

- 所有契约带 `schema_version`；v1 内只允许**向后兼容的新增字段**。
- 破坏性变更（删字段、改语义、改必填性）必须走 §10 的 ADR 修订。
- 所有 ID 为字符串；时间一律 RFC3339 带时区；禁止裸 `float` 时间戳进入契约层。
- 契约对象在跨部件传递后**不可变**；需要修改时创建新对象。
- 契约中不得出现明文密钥、完整本机路径、跨会话隐私数据。

### 4.2 Turn

```text
Turn {
  schema_version: int
  turn_id: string                 # 幂等：同一外部事件重复投递得到同一 turn_id
  session: {
    kind: "group" | "private"
    key: string                   # 群号；私聊为稳定会话 key
  }
  actor: {
    user_id: string
    display_name: string
    role: string                  # member / admin / owner / system
  }
  received_at: timestamp
  text: string                    # 已去掉媒体占位符的人类可读文本；可为空
  media: MediaRef[]               # 本条消息携带的媒体
  quote: {
    turn_id: string | null        # 能解析到历史轮次时填
    text: string                  # 被引用正文；拿不到则为空
    media: MediaRef[]
    unresolved: bool              # 拿不到原文/媒体时为 true，禁止猜测填充
  } | null
  addressed: boolean              # 是否明确对 bot 说（@ / 私聊 / 点名 / 协议前缀）
  task_refs: TaskRef[]            # 与本轮相关的长任务（可为空）
  flags: map<string, bool>        # 会话/策略标记，如 test_mute、silent
  source: {
    adapter: string               # 例如 "napcat"
    event_id: string              # 外部事件 ID，用于幂等与审计
  }
}
```

**不变量**

1. `turn_id` 由 `(adapter, event_id)` 确定性生成；重复投递不得产生两条 Turn。
2. Turn 在 Adapter 产出后不可变；任何补充信息（如引用解析结果）只能以新字段或新对象表达。
3. `text` 与 `media` 分离：不得把图片 base64、临时路径塞进 `text`。
4. `quote.unresolved = true` 时，核心必须能看到「引用未解析」，不得假装看过。
5. 私聊 Turn 的 `session.key` 与群 Turn 永不混用；Memory/Media 的 Scope 由此派生。
6. Turn 不携带任何模型生成的描述；描述属于 Evidence 或 MediaRef 的派生字段，需标注来源。

**现状**：`parse_message()` 返回 `(文字, 是否@, @了谁, 引用说明)` 四元组，非文字段被压成占位文本；图片由调用方另行提取并以 OneBot 段字典传递；引用在多个分支各自解析；历史只存文本。**未实现。**

### 4.3 MediaRef

```text
MediaRef {
  schema_version: int
  media_id: string
  kind: "image" | "video" | "audio" | "file"
  status: "pending" | "ready" | "failed"
  mime: string | null
  bytes: int | null
  sha256: string | null
  width: int | null
  height: int | null
  duration_ms: int | null
  local_uri: string | null        # 仅 MediaStore/工具可见，禁止进入 Prompt
  origin: "current" | "quote" | "forward" | "recall" | "generated"
  access_scope: "session" | "actor" | "global"
  created_at: timestamp
  expires_at: timestamp | null
  error_code: string | null       # status=failed 时给出可读分类
  derived: {
    caption: string | null        # 自动描述（若有）；必须标注由哪个模型/版本产生
    caption_model: string | null
  } | null
}
```

**不变量**

1. 字节只存在于 MediaStore；MediaRef 本身不携带内容。
2. `local_uri` 永不出现在模型 Prompt、群消息、日志明文或 MCP 返回值中。
3. `status = failed` 必须能被核心看到；不得静默丢弃。
4. `sha256` 相同可去重，但访问控制仍按 `access_scope` 判定，不得因为去重而跨会话可见。
5. `derived.caption` 是辅助信息，不得替代原图成为唯一上下文；核心能拿到原图时必须给原图。
6. 过期不等于删除；过期只影响召回，物理删除由 MediaStore 的保留策略执行。

**现状**：`_msg_images`（按 mid 的定长缓存）、`_vg_assets`（30 分钟 per gid/uid）、`_keep_seen`（文字写进 HISTORY）三套并存；所有视觉/画图入口只取 `imgs[0]`。**未实现。**

### 4.4 ToolSpec

```text
ToolSpec {
  schema_version: int
  name: string                    # snake_case，全局唯一
  version: string                 # 语义化版本
  description: string             # 给模型看的能力说明，不含实现细节
  input_schema: JSONSchema        # draft 2020-12
  output_schema: JSONSchema
  scope: "public" | "owner" | "admin" | "system"
  side_effect: "none" | "session" | "external" | "irreversible"
  requires_confirmation: boolean  # irreversible 必须为 true
  idempotency: "none" | "key" | "natural"
  timeout_ms: int
  budget_class: "fast" | "normal" | "long"
  rate_limit: { per_minute?: int, per_hour?: int, per_day?: int } | null
  requires: ("turn" | "media" | "quote" | "task")[]
  dry_run: boolean                # 是否支持只校验不执行
  audit: { log_args: boolean, redact_fields: string[] }
}
```

**不变量**

1. 没有 `ToolSpec` 的能力不可被核心调用。
2. 权限只由 `scope` + Registry 策略判定；handler 内部不得再维护一套权限真相。
3. `side_effect = irreversible` 的工具必须要求确认，且只能在主人/管理员 Scope 下执行。
4. 工具的执行结果只通过 `ToolResult` 返回；不得直接发送消息。
5. 参数校验失败必须在 Registry 层拒绝，不得进入能力实现。
6. 工具名一旦发布不得复用为不同语义；废弃走 `deprecated` 标记与新名字。

**现状**：`_BOT_TOOLS` 9 个、`_QQ_TOOLS` 5 个、MCP 20 个，参数/权限/返回各一套；权限散落在 handler。**未实现。**

### 4.5 ToolResult

```text
ToolResult {
  schema_version: int
  tool_call_id: string
  ok: boolean
  code: string                    # 稳定错误码，例如 "no_media" / "timeout" / "forbidden"
  data: object | null             # 结构化结果
  user_text_hint: string | null   # 内容提示，不是最终话术；Renderer 负责表达
  artifacts: MediaRef[]           # 工具产生的媒体
  retryable: boolean
  error: {
    code: string
    message: string               # 可给用户看的简述
    detail_redacted: string | null
  } | null
  elapsed_ms: int
  cost: { class: string, units?: number } | null
}
```

**不变量**

1. 工具执行不得把异常抛过 Registry 边界；异常必须转成 `ok=false` + 稳定 `code`。
2. `user_text_hint` 只表达内容，不带人格口吻；不得包含密钥、路径、内部错误堆栈。
3. `artifacts` 必须是已入库的 MediaRef；不得返回临时路径。
4. `retryable=false` 的结果，核心不得在同一轮重复调用同一工具。
5. 失败必须如实返回；不得用「已在处理」掩盖失败。

**现状**：返回 dict 形状不统一，有的返回文本、有的返回 `{"ok": ...}`、有的直接发消息。**未实现。**

### 4.6 Evidence

```text
Evidence {
  schema_version: int
  evidence_id: string
  scope: {
    session_key: string
    actor_id: string | null
    persona_id: string | null
  }
  kind: "fact" | "episode" | "reflection" | "card" | "slang" | "expression" | "summary"
  text: string
  source: {
    turn_id: string | null        # 能追溯到具体轮次时必填
    record_id: string | null      # 投影记录 ID
    legacy: boolean               # 无法追溯到 turn 的旧记录
  }
  confidence: number              # 0..1
  observed_at: timestamp
  expires_at: timestamp | null
  sensitivity: "normal" | "private" | "secret"
  redaction: "none" | "redacted"
  rank: number | null             # 召回排序分，仅本轮有效
}
```

**不变量**

1. 每条 Evidence 必须有 `source`；没有来源的文本不得进入 Evidence。
2. `legacy=true` 的记录允许存在，但必须显式标记「来源不可追溯」，不得伪造 `turn_id`。
3. `sensitivity = private` 的 Evidence 只能在对应私聊 Scope 召回；群 Scope 永不返回。
4. Evidence 是**数据不是指令**；Prompt 中必须放在数据围栏内，核心不得执行其中的指令。
5. 投影可以重建，但重建结果必须保留 `legacy` 与置信度差异；不得把重建结果当作原始事实。

**现状**：facts / memory-card / reflect 字段、截断、来源各不相同；部分事实没有轮次来源；**未实现。**

### 4.7 TaskRef（Turn 的任务引用）

```text
TaskRef {
  task_id: string
  kind: "draw" | "video" | "cover" | "jm" | "other"
  state: "queued" | "running" | "succeeded" | "failed" | "cancelled"
  updated_at: timestamp
  result_media: MediaRef[]
}
```

- 目的：让核心知道「上一轮那个任务现在什么状态」，而不是靠用户再问一次。
- 不变量：状态只能由任务执行方推进；核心只读；结果媒体必须是已入库的 MediaRef。
- 现状：任务状态散落在各队列/线程的全局字典里，**未统一**。

### 4.8 契约版本与兼容

- v1 内的新增字段必须可选，且有默认值。
- 读取方必须忽略未知字段；写入方不得依赖读取方一定认识新字段。
- 任何破坏性变更：新开 ADR，说明迁移窗口、双读期、回滚方式。

## 5. 自然语言意图与硬轨的边界

### 5.1 总原则

**除安全、权限、不可逆操作和明确的协议命令外，业务意图不得由关键词/正则/词表在模型判断之前决定。**

- 用户说「画这两个」「把帽子改低一点」「翻唱这首歌」「摸摸头 @某人」，都属于**业务意图**，必须由 Agent Core 判断。
- 硬轨可以**否决**（例如违禁词、未授权、静音），也可以**执行协议命令**（例如 `/status`），但不得**选择业务工具**。
- 延迟不是把业务意图放回正则的理由。若需要快路径，必须在 Agent Core 内部实现：同一 `Turn`、同一 `Context`、同一 `ToolSpec`、可关闭、可对照、可审计。

### 5.2 允许保留的硬轨（穷举）

| 类别 | 允许内容 | 约束 |
|---|---|---|
| **安全** | 违禁词处置、骚扰/称呼硬闸、出站密钥与路径审计、熔断与限速 | 只能拦截或改写安全相关内容，不得借机选择业务动作 |
| **权限** | 管理员命令鉴权、仅主人、群白名单、会话开关、测试静音 | 只能否决或放行，不得解释自然语言 |
| **不可逆操作** | 写配置、删文件、执行命令、向其他会话发送、修改长期记忆 | 必须显式语法 + 二次确认 + 主人/管理员 Scope |
| **协议命令** | `/status` `/reset` `/silent` `/active` `/role` `/roles` `/mute` `/unmute` `/welcome` `/help`、`.jm <id>` 等 | 必须**完整匹配**、命令词可枚举、文档可查；不得使用 `contains` |
| **传输层** | 重复 message_id 去重、自身消息忽略、编码/分片 | 与业务意图无关 |

### 5.3 目标处置表

| 现有分流 | 目标处置 |
|---|---|
| `_route_admin_slash` | 保留为协议硬轨（Policy），迁出 `_handle_message` |
| `_route_ban_words`、`_bro_gate`、`audit_ok` | 保留为安全硬轨（Policy） |
| `_route_early_cmds` 的显式命令 | 保留为协议适配器 → ToolCall |
| `_route_media_cmds` 的自然语言匹配 | **退役为意图层**；handler 保留为工具 |
| `_route_draw_and_moss_cmds` | **退役为意图层**；画图/反推/改图成为工具 |
| `_route_master_auto_reverse` | 保留为显式主人策略（开关控制），不作为自然语言意图层 |
| `_route_bare_draw_and_submit`、`parse_draw` 的意图判断 | **退役**；只保留提示词/档位/比例的参数归一化 |
| `_route_ai_draw` | **合并进 Agent Core**（核心始终判断，而不是兜底） |
| `_route_moss_edit_pic`、`_route_private_recall_vqa` | **退役**；改图成为工具，回捞成为 Assembler/Media 行为 |
| `_route_video_cmds` | 协议部分（复位）保留；自然语言生成/反推成为工具 |
| `_route_link_and_keywords` | URL 识别作为信号；最新图/随机画成为工具；用户自定义关键词降级为显式策略（DEFER 另行裁决） |
| `_route_pic_only_chat`、`_route_group_ambient` | 合并进核心的调度策略 |
| `_route_brain_reply` | 合并进核心入口 |

### 5.4 禁止事项

- 禁止新增用于「判断用户想干什么」的自然语言正则。
- 禁止用 `contains` 做业务意图匹配。
- 禁止在 Handler 内直接发消息（Renderer 之外）。
- 禁止以「模型可能判断慢/贵」为理由，在核心之前恢复关键词路由。
- 禁止把安全硬轨扩展成业务规则（例如以「防止误画」为名，把所有「画」开头都拦成画图）。

### 5.5 协议适配器的边界

- 协议适配器只做两件事：识别**完整命令语法**、把参数映射为 `ToolCall`。
- 它不持有自己的发送逻辑、不维护自己的权限判断、不产生业务话术。
- 同一能力只允许一个协议语法；新增语法必须登记到文档与测试。

- 每个阶段的验收标准以本文件列出的条目为**唯一门槛**。

- 验收证据必须可复现：命令、日志、对比数据、diff 范围。

### 7.5 回滚原则

1. **开关回滚**：每阶段都有独立布尔开关，默认关闭；关闭即恢复旧路径。
2. **代码回滚**：每阶段一个（或一组）可单独 revert 的 commit；不与其他重构混合。
3. **数据回滚**：迁移前备份；优先 copy-on-write；M6 前不做破坏性迁移。
4. **双读期**：新服务与旧存储并行读取，对比结果；确认一致后才停止旧写入。
5. **旧路径保留**：验收通过 + 稳定性窗口 + 主人批准之前，不删除旧路径。
6. **回滚演练**：每个阶段启用前先演练一次回滚，记录耗时与数据完整性。

## 8. 当前未决架构问题

> 以下问题**尚未拍板**。本 ADR 只记录问题、约束与决策期限，不预设答案。任何实现不得在未拍板前自行选择默认方案。

### 8.1 事件日志如何从现有数据无损建立

**问题**：目标架构以事件日志为真源，但现有 `turns / facts / memory-card / reflect / slang / expression` 字段与来源不一致，部分事实没有轮次来源，`HISTORY` 只在内存。

**已知事实**（基线）：
- `maimem.db`：`turns` 400 行、`facts` 41、`people` 26、`person` 33、`fact` 42、`reflect_item` 307。
- `memory-card.json` 220 条，通过 `turnCursor` 增量摄取。
- `reflect` 有独立游标；`facts` 不保证带 `turn_id`。
- `bot.log` 有历史消息文本，但没有稳定的外部事件 ID 可用于精确回填。

**必须在 M5 前决定**：
1. 事件日志的最小字段与幂等键；
2. 旧记录的可追溯性分级（可追溯 / 可推断 / 不可追溯）；
3. 不可追溯记录的处置：`legacy=true` 只读，还是保留原存储不迁移；
4. 是否允许从日志回填，以及回填的误差如何标注；
5. 「无损」的验收口径：字段齐全、来源可追、无重复、无丢失，还是仅行为等价。

**当前默认**：不建立新日志，不迁移，不合并；现有存储继续按原逻辑运行。

### 8.2 人格与决策的边界

**问题**：人格应该只影响表达，还是也参与价值判断与动作选择？

**候选方向**（未选）：
- A. 人格只影响表达（identity + style），价值判断由安全策略与核心承担。
- B. 人格包含声明式 policy（可接受的互动方式、沉默偏好、边界），由核心在执行前评估，但安全硬轨优先。
- C. 人格作为独立规划器参与决策（风险最高，需证明不会越权）。

**必须在 M2/M5 前决定**：
1. 人格能否否决工具调用；
2. 人格能否改变「说/不说」的判断；
3. 人格与安全硬轨冲突时的优先级（安全必须优先）；
4. 人格切换时，历史记忆与投影的归属规则。

**当前不做决定**：保持现有人格注入行为；在拍板前，不得新增人格对工具调用、安全或权限的否决权。

### 8.3 工具权限的统一方式

**问题**：权限应该由 Registry 的声明式 `scope` 统一判定，还是保留各 handler 的现状判断？

**候选方向**（未选）：
- A. `ToolSpec.scope` + 中央 Policy 判定（声明式，需证明能覆盖所有现状例外）。
- B. 每个工具自带权限函数（灵活，但会重新分散）。
- C. 能力令牌（capability token）随 Turn 下发（安全，但实现复杂）。

**必须在 M3 前决定**：
1. QQ 角色、主人、群白名单、会话开关、私聊/群差异如何映射到 `scope`；
2. 需要二次确认的工具清单与确认方式；
3. MCP 与 HTTP API 是否复用同一权限判定；
4. 工具内部现有的资源闸（ComfyUI 队列、冷却、显存）算权限还是算执行约束。

**当前默认**：现有 handler 内的权限判断继续有效；Registry 只做影子校验，不取代。

### 8.4 MediaStore 的生命周期与权限

**问题**：媒体保存多久、谁能读、如何删除、如何跨轮/跨会话使用？

**必须在 M2/M5 前决定**：
1. 不同 `origin` 的 TTL（当前 30 分钟只是 `_vg_assets` 的局部规则）；
2. 磁盘配额与清理策略；
3. 私聊媒体能否被群上下文引用（未定）；
4. 用户要求删除时，是否连同记忆中的描述一起删除；
5. 生成物（画图/视频/翻唱）是否与输入媒体同一生命周期；
6. 是否需要加密或脱敏存储。

**当前默认**：不新建 MediaStore；三套缓存保持现状；不改变任何 TTL。

### 8.5 Agent Core 的循环终止与预算控制

**问题**：一轮对话允许几次模型调用、几次工具调用、多长时间、多少成本？预算耗尽时如何收尾？

**候选机制**（未选）：
- 最大轮次（当前工具循环上限为 8，但新核心需要重新定义）；
- 墙钟预算（当前存在 `ai.tool_budget_sec` 之类的局部预算）；
- token / 成本预算；
- 重复调用检测与失败停止；
- 预算耗尽时：如实告知未完成，还是要求核心给出当前最佳答复。

**必须在 M1（影子预算）与 M4（画图延迟）前决定**：
1. 每轮默认预算与上限；
2. 长任务（视频/翻唱）如何与对话预算隔离；
3. 预算耗尽的行为与话术；
4. 影子期的采样率与成本上限；
5. 终止条件必须覆盖：成功、失败、超时、预算耗尽、重复调用、需要用户澄清。

**当前默认**：沿用现有 `_TOOL_MAX_ROUNDS=8` 与局部预算；不改变任何运行值。

### 8.6 其它未决项（不阻塞当前阶段）

- 协议命令的最终清单与命名空间（是否统一到 `/`）。
- 用户自定义关键词规则（`config.keywords`）在新架构中的归属：策略、工具还是停用。
- `/admin` 与 `/console` 的退役顺序与覆盖度标准。
- `patrol_bot.py`、`webai` 链等低频能力的最终去留（当前一律保留）。
- RRF 等默认关闭检索能力的启用条件（当前禁止开启）。

## 9. 兼容、数据与运行约束

### 9.1 兼容策略

- 配置：新增键必须有默认值；旧键继续可读；不改变现有默认行为。
- API：`/api/*` 与 MCP 的参数/返回在迁移期保持向后兼容；新增字段可选。
- 工具：旧工具名继续可用；新 Registry 通过 adapter 兼容旧参数。
- 人格：`roles/*.md` 格式不变；人格切换行为不变。
- 消息：发送格式、分条、拟人、审计语义不变。

### 9.2 数据策略

- **不假定无损合并**：见 §6.4。
- **不删除**：M6 之前不删除任何表、列、文件、缓存。
- **先备份后迁移**：任何写操作前备份；优先 copy-on-write。
- **双读对账**：新服务与旧存储并行读取，逐字段对比。
- **legacy 标记**：无法追溯来源的记录显式标记，不伪造来源。
- **可重建性验证**：投影必须能从事件日志重建，或明确声明不可重建并保留原存储。

### 9.3 运行约束

- 不开启 `Purpose`、`Timing`、RRF 等默认关闭功能。
- 不改变任何现有开关默认值。
- 不修改生产配置、数据库、运行状态（本 ADR 阶段）。
- 不影响正在执行的 R1；不修改已通过的 R3。
- 不触碰其他会话的未提交工作。

### 9.4 禁止事项汇总

1. 禁止把设计目标写成已实现事实。
2. 禁止认定现有记忆存储可无损合并。
3. 禁止提前删除旧路由、旧表、旧缓存、旧能力实现。
4. 禁止开启默认关闭的功能。
5. 禁止新增自然语言业务意图正则。
6. 禁止在 Renderer 之外发送用户可见消息。
7. 禁止在 Registry 之外执行工具。
8. 禁止修改其他会话的未提交工作。

## 10. 变更控制

### 10.1 冻结与修订

- 本文件为 v1.0 冻结版；冻结后不得静默编辑。
- 修订必须：主人批准 → 升版本（v1.1 / v2.0）→ 记录变更理由与影响范围 → 更新受影响阶段的验收标准。
- 破坏性契约变更必须新开 ADR，并在其中说明迁移窗口、双读期与回滚方式。

### 10.2 阶段验收的冻结

- 每阶段验收标准以 §7.3 为准，是**唯一门槛**。
- 阶段完成后不得追加非阻塞性要求；改进项进入后续阶段或 backlog。
- 阻塞性问题必须先修订 ADR，再继续实施。
- 验收证据必须留档：命令、日志、对比数据、commit、diff 范围。

### 10.3 责任边界

- 设计变更：主人批准。
- 实施与验收：按阶段执行，每阶段独立报告。
- 数据删除：仅在 M6，逐批批准。
- 运行开关：默认关闭；开启需主人明确指令。
