## 一、本期实现：检索 RRF 融合 + 动态阈值（默认关）

现状：`qbot_memory.recall()` 是线性加权（语义 0.55 / 关键词 0.30 / 份量 0.15），
`recall_min=0.20` 固定地板。问题：三路分数尺度不同，换 embedding 或关键词命中数波动时
排序会漂。

新增（`qbot_memory.py`）：

```python
memory.fusion = "linear"      # linear | rrf；默认 linear = 旧行为逐字节不变
memory.rrf_k = 60             # RRF 常数
memory.rrf_dynamic = True     # RRF 模式下按本次候选 P75 取阈值
memory.rrf_min_results = 4    # 动态阈值至少保留几条
```

- `_rrf_rerank(scored, cfg)` 纯函数：三信号各自排名 → `Σ w/(k+rank)` →
  归一化到 0~1（保证 `recall_min` 继续有效）→ P75 动态收缩（至少 4 条）。
- 只在 `fusion=="rrf"` 时生效；`linear` 路径一行没动。
- 没有新增旋钮/控制台项（避免实验期污染界面）；切换是改 `config.json` 的 `memory` 段
  → 重启生效。评估完再决定是否开成网页项。

`tests/_tmemfusion.py`（SAFE，全离线，临时库）：

## 四、如何试用 / 回滚

⚠️ **不要和 C 的实验同时开**（2026-11-04 主人定）：RRF 默认保持 `linear`，
等 C 的 observation/主动发言实验有结论后再单独切换，才能归因是「记忆排序」还是「开口机制」带来的变化。

试用（只影响记忆注入，不影响发送闸）：

```json
"memory": {"fusion": "rrf"}
```

重启后 `grep 记忆检索` 无异常即可观察；回滚把 `fusion` 改回 `"linear"`（或删掉该键）。

⚠️ RRF 会改变「往 prompt 里塞哪几条旧记忆」，属于**可见行为变化**；建议先在低峰期试一天，
对比模型是否更少提不相干旧事、更少漏掉刚聊过的硬关键词，再决定是否长期开启。

## 五、风险

- 动态阈值在候选很少（<4）时自动跳过，不会把结果删空；
- 归一化分数让 `recall_min` 的语义从「绝对分」变成「相对本次最高分的比例」——
  这是 RRF 模式下有意为之（换模型不用重调参），但预算注入条数仍由 `recall_n/recall_chars` 硬限；
- 状态无新增落盘文件，回滚零残留。
