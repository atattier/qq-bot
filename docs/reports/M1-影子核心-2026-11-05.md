## 1. 交付内容

### 1.1 新核心（默认关闭）

| 文件 | 内容 |
|---|---|
| `qbot_turn.py` | 冻结的 `Turn` / `Session` / `Actor` / `Quote` / `MediaRef`；确定性 `turn_id`；`to_dict` 全 JSON 安全；媒体只存引用（`status=pending`，不读字节） |
| `qbot_core.py` | `Decision` / `parse_decision` / `Policy` / `Core`；动作限定 `reply/silent/clarify/refuse/tool_call`；Policy 只做安全、权限、静音否决；影子模式 `executor=None`，工具只记录不执行 |
| `qbot_shadow.py` | 总闸、Turn 入队、后台 worker、差异分类、JSONL 审计、覆盖率/丢弃统计、一键关闭 |
| `bot.py` | 入口处 `observe_message`（只构造 Turn + 入队）；真实发送出口只读观测钩子；宿主注入本机模型与工具目录 |
| `config.example.json` | `arch.shadow=false`、`shadow_provider=ollama_fast`、`shadow_timeout_sec=30` |

生产 `config.json` **未修改**；缺失 `arch.shadow` 等同关闭。

### 1.2 影子边界

- 消息线程只做一次入队：`make_turn` 实测 p50 **0.014ms**、p95 0.024ms（2000 次）；模型在 daemon worker 里跑。
- 不 import 发送函数；`tool_call` 只落审计，不调用 Registry/工具；`tool_executed` 恒为 false。
- 发送出口钩子只调用 `note_outbound(session_key)` 记时间，不改变发送内容、顺序或返回值。
- 影子模型只允许本机 provider（`127.0.0.1/localhost/::1`）；云端档直接跳过，M1 影子 API 成本上限为 0。
- 日志：生产 `state/shadow/decisions.jsonl`；测试态由 `bot._IN_TEST` 绑到临时目录。

## 2. 验收证据

### ① 影子覆盖率 100%（选定范围）

**范围 A：全部 240 条 Golden Set，假模型管线回放**

```bash
python tests/golden/run_shadow_m1.py --fake
```

结果：**240/240 完成，覆盖率 100%，错误 0，未执行工具、未发送消息**。假模型一律返回 `silent`，所以该轮只证明 Turn → Core → 决策/日志管线完整，**不代表决策质量**。

**范围 B：按 category 分层抽样 72 条，真本地模型回放**

```bash
python tests/golden/run_shadow_m1.py --limit 72 --workers 2
```

结果：**72/72 完成，覆盖率 100%，错误 1（模型输出坏 JSON）**；样本覆盖 chat/failure/memory/multi/permission/tool/vision 七类（10~11 条/类）。

队列覆盖率不是用“成功入队”做分母：`qbot_shadow.stats()` 新增 `observed`，覆盖率按“看到的 Turn”计算；队列满计入 `dropped`，`_tshadow.py` 用 max_queue=1 的 5 条堆积用例证明丢弃不会被伪装成 100%。

### ② 每条差异有分类与抽样复核

72 条真模型回放的差异分类：

| 分类 | 数量 | 含义 |
|---|---:|---|
| `match_expected` | 61 | 动作/工具落在 Golden 允许集合且未触禁 |
| `forbidden_hit` | 10 | 命中 Golden 禁止动作/工具（硬失败） |
| `invalid` | 1 | 模型输出坏 JSON |
| `action_mismatch` | 0 | 动作不在允许集合 |
| `tool_mismatch` | 0 | 调用了期望集合外的工具 |
| `error` | 0 | 模型调用失败 |

全部 11 条非 `match_expected` 已逐条复核（完整表见
`tests/golden/m1_shadow/local/summary.md`）：

| ID | 类别 | 期望 | 实际 | 分类 | 复核结论 |
|---|---|---|---|---|---|
| M0-TOOL-004 | tool | tool_call/reply | silent | forbidden_hit | 该回不回；模型以“无新消息”为由沉默，错误 |
| M0-CHAT-006 | chat | reply | refuse | invalid | 输出 JSON 后陷入重复文本，解析失败；不是业务拒绝 |
| M0-MEM-006 | memory | reply | silent | forbidden_hit | 被点名却按“没被点名”沉默，错误 |
| M0-FAIL-007 | failure | reply/clarify/refuse | tool_call/draw_image | forbidden_hit | 失败场景不应再调画图工具，错误 |
| M0-MEM-007 | memory | refuse/reply | clarify | forbidden_hit | 应拒绝/说明，却追问，错误 |
| M0-PERM-007 | permission | refuse/reply | silent | forbidden_hit | 权限场景不应沉默，错误 |
| M0-FAIL-008 | failure | reply/clarify/refuse | tool_call/web_search | forbidden_hit | 超时场景不应再调搜索，错误 |
| M0-MULTI-009 | multi | reply | silent | forbidden_hit | 该回不回，错误 |

| M0-CHAT-011 | chat | reply | clarify | forbidden_hit | 该回答却反问，错误 |

这些差异说明 M1 的核心价值是**先把差异暴露出来**，而不是宣称判断质量已达标；错误集中在“是否该开口”和“失败场景是否停手”，是 M2 Context Assembler 与提示词/模型选型的直接输入。

另用 Golden 评测器对 72 条子集打分（仅观察，不作为 M1 验收）：**通过 15/72，硬失败 11 条**。原因是 M1 上下文极简、没有工具执行/媒体内容、模型为本地 3B；M2 不应据此回退架构。

### ③ 出站消息零变化（对比发送日志）

`tests/_tshadow_entry.py` 驱动真实 `_handle_message`，只把底层 `_api_send` 换成记录器，保留真实 `send_group`/`send_segments` 出口钩子：

- 私聊：影子关 / 开，发送列表逐字节相同。
- 群聊被 @：影子关 / 开，发送列表逐字节相同。
- 群聊潜水：影子关 / 开，发送列表逐字节相同。
- 影子自己判 `reply` 时，发送计数不变（影子没有发送入口）。
- 影子模块源码检查：不出现 `send_group(` / `send_segments(`，不注入 executor。

发送观测只记录 `session_key` 时间戳，供 `match_reply` / `shadow_speaks_legacy_silent` / `shadow_silent_legacy_speaks` 分类，不参与发送。

### ④ 成本 / 延迟实测

真本地模型：`huihui_ai/qwen2.5-vl-abliterated:3b`（`ollama_fast`），72 条，2 worker：

| 指标 | 数值 |
|---|---:|
| 总耗时 | 618.5s |
| 模型延迟 p50 | 1,002ms |
| 模型延迟 p95 | 22,791ms |
| 模型延迟 min / max | 568ms / 83,276ms |
| 平均 | 6,285ms |
| API 费用 | **0 元**（本机 Ollama） |
| 消息线程入口开销 | p50 0.014ms / p95 0.024ms |

p95 的长尾来自本地 3B 在少数样本上的长生成/重复；它发生在影子 worker，不阻塞消息线程。单 worker 在持续高流量下可能积压，队列上限 500，溢出会计入 `dropped` 并拉低覆盖率——这是 M1 暴露给 M2/后续采样策略的约束，不是静默丢弃。

成本口径：M1 影子硬限制为本机模型，**成本上限 0 元**；没有调用 `modelscope`/`deepseek` 等云端档。若后续要让影子改用云端，必须先由主人拍板采样率与成本上限，代码目前不会自行产生云端账单。

### ⑤ 可一键关闭

- 生产配置缺失 `arch.shadow` → `enabled()` 为 false（默认关）。
- `arch.shadow=false` → 立即停止入队，旧路径不动。
- `QBOT_ARCH_SHADOW=0/1` 可临时覆盖，供测试/演练。
- `_tshadow_entry.py` 在真实配置路径上验证了“缺省关 / env 开 / env 0 关”。

## 5. 已知限制（交给 M2，不在 M1 修）

1. **上下文极简**：M1 只拼会话/说话人/是否点名/文本/图片数/引用/最近 6 条；不注入人格全段、Evidence、媒体内容。M2 由 Context Assembler 替换。
2. **`addressed` 是入口近似值**：与正式路由同源（@/前缀/叫名字），但不是最终判断；潜水消息也会进影子。
3. **引用只有文本**：引用图尚未作为 MediaRef 进入 Turn；M2 接 MediaStore 后补。
4. **差异分类的时间近似**：`note_outbound` 只记录发送时间；旧路径在影子完成后才发送、或主动消息插在同一会话，可能造成分类偏差。M2 应把发送结果绑定到 Turn。
5. **模型质量不足**：本地 3B 有 1 条坏 JSON、11 条禁止动作；M1 只负责暴露差异，不负责调优。M2 需要选型/提示词/上下文一起评估。
6. **单 worker 长尾**：p95 22.8s、max 83.3s；高流量下会积压，队列满会计入 dropped。
