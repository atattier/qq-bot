动手前做了依赖检查，推翻了我自己 12:5x 提的建议——另外两个插件不能禁， 禁了会直接搞坏你的主力出图链。所以真正的大头（vrgdg 4.80 MB）保持不动。

这次改动不是主因的解：1~2 分钟延迟来自「39 插件 / 652 脚本 / 3754 节点」这个量级本身， 砍单个插件最多是个位数百分点。下一步该往浏览器端找。

二、已执行的改动

操作目录改名加 .disabled 后缀（没有删除任何文件） 命令mv custom_nodes/ComfyUI-Danbooru-Gallery → ComfyUI-Danbooru-Gallery.disabled 生效机制ComfyUI 只认目录名以 .disabled 结尾（nodes.py:2377） 回滚去掉 .disabled 后缀即可，目录完整 状态已落盘，等你启动 ComfyUI 生效
⚠️ 运行中改会 Permission denied（进程持锁，12:53 试过失败），必须 ComfyUI 关闭时改。 启动方式 = 绘世启动器.exe 图形启动器， 所以 --disable_all_custom_nodes 那套白名单参数用不了（改不了启动参数）， .disabled 目录法是唯一可行手段。

三、诚实的收益评估

前端 JS20.71 MB → 18.56 MB（−10.4%） object_info7.50 MB → 7.49 MB，少 10 个节点种类（仅 −0.14%） 最大头没动vrgdg 4.80 MB（占 23%）—— 你主力，不动

所以：这一改大概能把「一两分钟」往「一分半」拉一点， 但不会质变。真正的量级问题是 39 插件 / 652 脚本 / 3754 节点这个规模， 而其中占比最大的几个都不能砍。

四、下一步建议（等你决定，我不动手）

  • 开 F12 → Performance 录一次「点运行」，看时间花在哪。这是唯一能定位真凶的办法。
    如果时间大头在 graphToPrompt / 节点注册 → 确实是前端负载； 如果在别处（比如某个 beforeRegisterNodeDef 钩子）→ 那就是某个插件的锅，能精准定位到单个插件。
  • 试无痕窗口跑一次（Ctrl+Shift+N）。无痕没有扩展插件。
    如果无痕明显快 → 是浏览器扩展的锅（广告拦截/脚本注入类），跟 ComfyUI 无关。
  • 排除浏览器因素：换一个浏览器（Edge/Chrome 互切）跑一次。
我倾向让你先做「无痕窗口」那一步——成本最低，而且能一刀切开「ComfyUI 的锅」还是「浏览器的锅」。 如果无痕也慢，那 F12 剖析就更有必要了。

五、工具（可复用）
