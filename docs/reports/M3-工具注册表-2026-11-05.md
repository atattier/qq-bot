### 1.1 一套契约

`ToolSpec` 冻结字段：`name / description / input_schema / scope / surface / side_effect /
idempotent / timeout_sec / group_only / private_only / constraints / aliases / http / source`。
构造时校验 `scope ∈ public|admin|owner|system`、`side_effect ∈ none|read|write|external|irreversible`、
`surface ∈ omni|mcp|http`，非法值直接失败（不静默降级）。

`ToolResult` 状态：`ok | error | denied | timeout | invalid | unsupported`，字段
`tool / ok / status / data / error / latency_ms / idempotent / replayed / schema_version`；
`from_legacy()` 兼容旧 dispatch 的两种返回形状（带 `ok` 的 bot 工具、只有数据键的 `qq_*` 查询）。

`Principal`：`source(chat|system) / role / is_master / is_privileged / is_group`。
**system 只给本机桥接与内部执行器**；聊天来的任何身份（包括主人）都不能满足 system 档。

### 1.2 总控工具面（14 个，全部登记）

scope = **工具面准入线**（`_omni_tools` 真正摘下/留下的那一条），不是 handler 里的资源闸。

| 工具 | scope | 副作用 | 幂等 | 超时 | 工具面约束 |
|---|---|---|---:|---:|---|
| `qq_groups` / `qq_members` / `qq_history` | admin | read | 是 | 15 | 仅 privileged |
| `qq_wait_new` | admin | read | 是 | 45 | 仅 privileged |
| `qq_send_group` | admin | irreversible | 否 | 45 | 仅 privileged |
| `remember` | admin | write | 否 | 10 | 仅 privileged |
| `draw_image`（别名 `cloud_draw`） | public | external | 否 | 60 | `allow_draw` |
| `draw_like_this` | public | external | 否 | 60 | `allow_draw` |
| `gen_video` | public | external | 否 | 30 | `allow_draw` |
| `reverse_prompt` | public | external | 否 | 60 | — |
| `web_search` | public | external | 是 | 25 | — |
| `recall_memory` / `bot_status` | public | read | 是 | 10 | — |
| `send_meme` | public | write | 否 | 20 | — |

### 1.3 MCP 工具面（20 个，全部登记）

20 个工具统一 `scope=system, surface=mcp`，每个都登记 HTTP 映射；`tests/_tregistry.py`
把 20 条映射逐条对到 `bot._API_GET_ROUTES` / `_API_POST_ROUTES`，**20/20 路由存在**。

### 1.4 权限矩阵

| 调用者 | public | admin | owner | system |
|---|---|---|---|---|
| 陌生人 / 群友 | ✅ | ❌ | ❌ | ❌ |
| 管理员（`is_privileged`） | ✅ | ✅ | ❌ | ❌ |
| 主人（`is_master`） | ✅ | ✅ | ✅ | ❌ |
| 本机桥接（`source=system`） | ✅ | ✅ | ✅ | ✅ |

`owner` 是 `admin` 的严格超集；`system` 与聊天身份完全隔离。

### 1.5 影子接线（不改变执行）

- `chat_once_tools` 在本轮开始记一条 `offer`：**现有工具面 vs 契约预期**的差异
  （`missing_spec / denied_but_offered / expected_but_absent / allowed_but_not_expected`）。
- 每次模型发起工具调用记一条 `call`：`in_spec / offered / executed / registry_allowed /
  registry_reason / result_ok / result_status / unauthorized_ok`。
- 唯一算“越权成功”的口径：**契约禁止 + 真的执行了 + 执行成功**（`unauthorized_ok`），
  这时才写 warning。工具面/预算/去重挡住的调用 `executed=false`，不算越权。
- 审计落 `state/tools/shadow.jsonl`（一行一条，不含参数正文与消息正文）；测试态由
  `bot.py` 的 `_IN_TEST` 统一改到临时目录，并已登记进 `tests/_tisolation.py`。
- 默认 `arch.tools=legacy`：**`offer`/`call` 一次都不写**，旧工具面逐项不变。

### 1.6 一键回退

| 操作 | 效果 |
|---|---|
| `arch.tools=legacy`（默认） | 影子完全关闭，工具面/执行/发送零变化 |
| `arch.tools=shadow` | 只写审计，不拦不改 |
| `QBOT_ARCH_TOOLS=legacy\|shadow` | 临时覆盖（优先于 config） |
| 写错/写超前的值（如 `registry`） | 一律按 `legacy`，绝不误开（执行权接管在 M4） |
| MCP：`QQBOT_ARCH_TOOLS=legacy`（默认） | `tools/list` 照旧直接吐原表 |
| MCP：`QQBOT_ARCH_TOOLS=registry` | `tools/list` 由 Registry 生成（逐项等价） |

## 2. 验收证据

### ① 所有可调用能力都有 `ToolSpec`

`tests/_tregistry.py` 第 1 节：

- 总控 14/14 有 spec（5 个 `qq_*` + 9 个 bot 能力），`coverage().clean=true`；
- MCP 20/20 有 spec，`coverage().clean=true`；
- 每个 spec 都有名字/说明/参数 schema/scope/副作用/幂等标记/超时；
- 别名 `cloud_draw → draw_image` 可解析；未登记工具不解析（`None`）。

### ② 权限矩阵覆盖 public / owner / admin / system

- 用 4 个合成 spec 覆盖 4 档 scope，对 5 类调用者（陌生人/群友/管理员/主人/桥接）
  做 **4×4 全矩阵**断言，逐格与预期表相等（第 2 节）；
- 真实工具面：群友 8 个公开能力、`allow_draw=False` 5 个、privileged 14 个，
  与 `bot._omni_tools(...)` **顺序与集合逐项相等**（无契约漂移）；
- `group_only` / `private_only` 两个会话维度各有正反用例；桥接不受会话类型限制；
- 主人也拿不到 system 档（不能冒充本机桥接）。

> 说明：当前聊天工具面没有“比 privileged 更严”的工具（主人 ⊂ privileged），所以
> `owner` 档用合成 spec 覆盖；M4 出现 owner 专属工具时直接套用同一矩阵。

### ③ 越权调用为零

三层证据：

1. **面与契约一致**：群友面、privileged 面、`allow_draw=False` 面的 `shadow_offer` 全部 `clean=true`；
2. **契约能抓越界**：把全量 14 个工具硬塞给群友，`denied_but_offered` 精确报出
   `qq_groups/qq_members/qq_history/qq_send_group/qq_wait_new/remember` 6 个；未点名画图
   被判 `denied_but_called`；
3. **真实工具循环拦截**（离线假网关）：群友这轮只拿到 5 个公开工具，模型硬写
   `qq_send_group` 与 `draw_image` 两个调用 → 两个都**没有执行**（执行器被替换成“调用即失败”，
   实际 0 次触发），两条拒绝如实回填给模型，影子记录 `executed=false`、`unauthorized_ok=0`。

### ④ 超时 / 幂等 / 失败返回符合 `ToolResult`

`ToolRuntime` 第 4 节：

| 场景 | 结果 |
|---|---|
| 正常执行 | `ok`, `status=ok`, `data` 带返回值 |
| 同一幂等调用重复 | 不重复执行，`replayed=true` |
| 非幂等工具重复 | 每次都执行（不复用） |
| 缺必填 / 类型不符 | `status=invalid`，**执行器未被调用** |
| 执行抛异常 | `status=error`，保留错误摘要 |
| 超过 `timeout_sec` | `status=timeout`，按预算返回（0.15s 预算 < 1s 实测） |
| 权限不足 | `status=denied`（`ToolResult.fail`） |
| 未知状态 | 构造时报 `ValueError`，不允许出现第七种状态 |

旧 dispatch 的字典结果经 `from_legacy()` 转成 `ToolResult` 后再进审计，不改变返回给模型的内容。

### ⑤ MCP 工具由 Registry 生成且参数兼容

- 默认：`list_tools() == TOOLS`；
- `QQBOT_ARCH_TOOLS=registry`：`list_tools()` 生成 20 条，与 `TOOLS`
  **逐项 `==`**（name/description/inputSchema 全等、顺序不变）；
- `dispatch_tool` 与改动前 **AST 逐字节相同**（用 `git show HEAD:qq-mcp-server.py` 对照），
  `tools/call` 仍走原映射；20 条 HTTP 路由全部存在于 bot 的兼容层。

### ⑥ 旧 dispatch 仍可回退

- `arch.tools=legacy`：审计文件一行都不产生（有“legacy 时一行审计都不写”断言）；
- `arch.tools=shadow` 写入 offer + call 后才产生审计；切回 legacy 不再新增；
- `_omni_tools(True)` / `_omni_tools(False)` / `_omni_tools(False, allow_draw=False)`
  的输出集合与顺序在 M3 前后完全一致；
- `chat_once_tools` 新增参数都有默认值，旧调用点（不传 principal）行为不变；
- MCP 侧 `dispatch_tool` 未动，`tools/list` 默认仍吐原表。

## 5. 已知限制（M3 之后的未排期工作）

> **编号更正（2026-11-05）**：本节早期写作「交给 M4」。按 ADR-001 §7.3，**M4 是画图 / 视觉域**，
> 不包含工具执行权接管。下面第 2、3、5 条属于 M3 之后的**未排期**工作，不是 M4 的验收项。
> 对照见 [`docs/阶段编号对照-ADR-001.md`](../阶段编号对照-ADR-001.md)。

1. **只影子不接管**：handler 里的权限仍是唯一执行闸；Registry 的 `check()` 结论只进审计。
   M3 也刻意不认 `arch.tools=registry`，避免误开。
2. **`owner` 档暂无真实工具**：当前 privileged = owner ∪ 可信群管，owner 是子集；
   矩阵用合成 spec 覆盖，之后出现 owner 专属工具时自动生效。
3. **审计无采样/无轮转**：一行一条 JSONL，长期打开需要按大小/按天轮转与保留期（未排期）。
4. **审计不记参数**：只记工具名、principal、结果状态与错误摘要；可追责但不可完整复现调用参数。
   这是刻意的（避免把用户正文/图片路径写进审计）。
5. **`ToolRuntime` 尚未进执行路径**：它现在是契约的可执行证明与测试替身；把 dispatch
   真正切到 `ToolResult` 需要改所有调用方，属于**未排期的执行权接管**（不是 M4）。
6. **MCP 只改了 `tools/list` 的来源**：参数校验、错误码、超时仍在 bot 的 HTTP 层；
   MCP 侧没有本地权限判断（桥接 token 即 system 身份）。
7. **影子按“每次工具循环”写 offer**：一轮里多次工具调用会有 1 条 offer + N 条 call，
   统计时要按 `kind` 分开聚合。

## 6. 结论

M3 把总控大脑（14）、MCP（20）两套可调用能力登记进同一份 `ToolSpec` 契约，并给
HTTP 兼容层逐条登记了路由映射；权限判定收敛为 public/admin/owner/system 四档且
system 与聊天身份硬隔离。按 ADR §8.3 当前默认，Registry 只做影子校验：工具面、
调用、越权成功全部可审计，而旧 dispatch 与发送路径逐字节未变。

| 验收条件 | 结果 |
|---|---|
| ① 所有可调用能力都有 `ToolSpec` | 通过：14 + 20，覆盖报告 `clean=true` |
| ② 权限矩阵覆盖 public/owner/admin/system | 通过：4 档 × 5 类调用者全矩阵 + 真实工具面 |
| ③ 越权调用为零 | 通过：面/契约一致；越界可被抓；假网关下两个越权调用 0 执行 |
| ④ 超时/幂等/失败返回符合 `ToolResult` | 通过：6 种状态、超时、幂等复用、非法参数不执行 |
| ⑤ MCP 由 Registry 生成且参数兼容 | 通过：20/20 逐项相等，HTTP 路由 20/20 存在 |
| ⑥ 旧 dispatch 仍可回退 | 通过：legacy 零审计、工具面不变、dispatch AST 未动 |
