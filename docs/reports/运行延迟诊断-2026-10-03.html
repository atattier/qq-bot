ComfyUI「点运行要等一两分钟才开跑」诊断报告

2026-10-03 · 结论：不是服务器问题，是浏览器前端负载爆炸 · ComfyUI 0.38.0 · RTX 4060 Laptop
一句话结论
服务器侧从「收到提交」到「开始执行」是 亚秒级（中位 0.35 秒）， 慢的那一两分钟全部发生在 浏览器把图提交过来之前—— 前端每次点运行都要重新校验 3754 个节点定义（7.49 MB） 和 39 个插件的 652 个 JS 扩展（20.71 MB）， 这是纯浏览器单线程 CPU活。

「所有工作流都这样」就是最强的证据：开销与工作流内容无关，只与装了��少插件有关。

为什么最大 91 秒？ 12:44:24 那次前端连着提交 5 次全被拒（prompt_no_outputs， 即「图里一个输出节点都没有」，execution.py:1167），第 6 次才受理——中间隔 91.2 秒。 而 12:53:56 那次 0.46 秒就开跑。同一台机器波动 100 倍 ⇒ 客户端 CPU 抖动，不是服务端。

浏览器解析 7.5 MB JSON + 注册 3754 个 LiteGraph 节点类型 + 初始化 652 个扩展脚本， 全是主线程同步 CPU 活。装了 39 个插件的这个规模，几十秒到一两分钟完全在预期内。

三、能怎么缓解（等你发话，我没动任何东西）

  • 禁用不用的插件前端扩展——目录改名加 .disabled 后缀即可（nodes.py:2369 会跳过）。
    首选目标：ComfyUI_Custom_Nodes_AlekPet（105 个脚本）、 ComfyUI-Prompt-Gallery-master（72 个）、ComfyUI-Danbooru-Gallery（41 个）—— 这三类是图库 / 打标用的，平时不出图根本用不到，却占了 5.3 MB 和 218 个脚本。
  • 硬刷新 Ctrl+Shift+R 清 JS 缓存，偶尔能缓解前端注册表膨胀（这大概就是 F5 反而变快的原因）。
  • 不要动 vrgdg（4.80 MB，单插件最大）——这是你主力用的。
每禁一个插件都需要重启 ComfyUI 才生效。收益预估：去掉上面三个图库类插件， 前端 JS 从 20.71 MB 降到约 15.4 MB（−26%），节点种类也会明显减少。

四、排查方法（下次照这个走，别再猜）

3量 /system_stats、/queue 延迟毫秒级→服务器无罪

两个踩过的坑：
