## 2. 交付物

### 2.1 新模块 `qbot_draw_intent.py`

纯模块，不 import bot、不发消息、不执行工具：

- **选图** `pick_media(turn, recent_turns)`：本轮图 → 引用图 → 最近同会话图；
  「这两个/这两张」取 2 张，「都画/这几张/全部」有多少取多少（上限 4）；
  按 `source` 去重（同一张图既在本轮又在回捞里时不会算两次）；不跨会话、不跨用户。
- **判意图** `SYSTEM` + `build_messages` + `parse_decision` + `decide`：
  五选一 `draw / edit / reverse / chat / ask`；只输出 JSON；严格校验动作、置信度、
  media id（只认清单里的 id，编造的丢弃）；超时/异常/解析失败一律 `intent=None`。
- **归一化** `normalize`：翻译成现有 handler 的参数（`draw_submit` / `handle_moss_edit` /
  `handle_moss_reverse`），`parse_draw` 从此只做参数归一化，不再拥有「要不要画」的解释权。
- **失败话术** `failure_text`：只说没做成和为什么，绝不假装已提交。
- **审计** `record`：只写元数据（动作/耗时/图数量/回退原因），不写原话与提示词。

### 2.2 接线 `bot.py`

- `_arch_draw_mode()`：`arch.draw` / `QBOT_ARCH_DRAW`，只认 `legacy|core`，写错一律 legacy。
- `_route_draw_core(...)`：排在**显式口令之后、关键词与意图正则之前**；
  - 群里没被点名 → 不跑（维持旧口径）；
  - 核心内快路径：没有图、也不含「画/图/改/渲染…」的闲聊不跑模型（省一次调用）；
  - 判出 `draw/edit/reverse` → 直接走现有 handler；`ask` → 追问；
  - 判出 `chat` → 本轮旧的画图/改图意图路由全部关闭（`_CORE_TLS.draw_chat`）；
  - 判定失败/超时 → 与 legacy **逐项同结果**（测试按结果相等断言）。
- `_core_recent_turns`：复用视频生成/看图回捞的 30 分钟素材记忆（`_vg_assets`），
  不新开缓存、不跨用户。
- 多图 → `compose_refs` 拼成一张（现有 `draw_submit` 的 i2i 与 moss 反推都只吃单张）。

## 4. 已知限制（必须写进交接）

1. **多图是「合成图垫片」**：`draw_submit`/moss 反推只接受单张参考图，M4 把多张拼成
   2 列网格送进去。它能保证「两张都带进画面」，但不是真正的多图条件生成；
   真正的多图 i2i 需要改 `qbot_draw_body.py` 的排队结构与 ComfyUI 工作流（下一阶段）。
2. **判定是额外的一次模型调用**：core 模式下，被点名且含图/含「画」字的消息会先跑一次
   意图判定，再由大脑回答。成本与延迟都会上升；这就是 ⑤ 要实测的原因。
3. **12 秒超时是线程超时**：`decide` 超时后回退 legacy，但底层请求线程仍会自然结束
   （daemon，不阻塞回复）。若网关极慢，日志里会看到「回退 legacy（timeout）」。
4. **主脑偶发抖动**：最终整跑唯一失分是 D-015「那两幅一起画成 Q 版」被判 `edit`；
   同一条事后连问 5 次都是 `draw`（5/5），属于单次生成波动，不是稳定规则错误（§7.2）。
5. **网关偶发慢请求**：一次中间整跑出现 3 条 12 秒超时，已按协议单列、不计成绩；
   评测把 case timeout 提到 20 秒后，最终 57 条无超时。生产默认仍是 12 秒（超时回退 legacy）。
6. **配置热更新**：本轮开始时 `custom` 还指着旧模型（429），主人切换为
   `minimax-code/MiniMax-M3.1-Flash` 后恢复；评测使用的是切换后的真实生产配置。
   `config_core` 不监听文件变化，长驻进程需重启才能看到手改的配置。

### 7.1 评测协议（脚本内强制，不靠人记）

- **只用主脑**：`--provider bot` 走 `bot.chat()`，和线上 `_route_draw_core` 完全同一条链；
  `--model` 只能作为离线夹具，报告里 `mode=local_fixture`，**成绩不计入主脑**。
- **先预检再开跑**：先用同一链路问一句「只回复 ok」。预检不是 primary/fallback
  （429、超时、只能落本地）就**中止**，不产出 57 条全 429 的假结果。
- **逐条记录** `backend` / `model` / `identity`（primary / fallback / local / unknown）
  与错误原因；本地 `ollama*` 兜底一律 `local_fallback`，**不计分**。
- **分桶单列**：`http_429` / `timeout` / `network_timeout` / `provider_error` /
  `model_mismatch`。有未计分样本时退出码 2，明确表示「这不是一份有效成绩」。
- **禁止动作**：期望 `chat/ask` 却判成 `draw/edit/reverse`，主脑与全部各记一份 id。
- **延迟**：p50/p90/max 分别按「有效样本」与「全部尝试」统计。
- **隔离自检**（`--selfcheck` 可单独跑）：`QBOT_TEST=1`；记忆库 / 心情 / 词库 / 现画状态 /
  影子日志 / 意图审计全部落在临时目录；`qbot_metrics` 在测试态不绑库；
  发送、出图、改图、反推、视频入口全部换成抛错桩，被碰到就记 `HARNESS VIOLATION`
  并以退出码 2 结束。自检不通过**拒绝运行**。

### 7.2 draw/edit 边界修订与唯一残余失分

第一次整跑的三条失分都是**对已有参考图做整体变换**（合成 / 拼接 / 重画成油画），
主脑判成了 `edit`：

| 用例 | 原话 | 期望 | 修订前 | 最终 |
|---|---|---|---|---|
| D-018 | 把上面那两张合成一张 | draw | edit | draw |
| D-022 | 把这三张拼成一张长图 | draw | edit | draw |
| D-028 | 把引用的图重画成油画 | draw | edit | draw |

按当前接线，`edit` 走 `handle_moss_edit`（对参考图做局部编辑），
`draw` 走 `draw_submit(..., i2i=参考图)`（生成新图）；多图整体合成只有 `draw` 符合语义。
主人拍板后，`qbot_draw_intent.SYSTEM` 增加规则 1b：
**「最后交出的是不是同一张画面」**——在给的那张图上动（改局部、换背景、调色、去水印、
加字，含「这两张都改成黑白」）是 `edit`；要另一张新图（多张合成、拼接、重画成别的风格、
按参考图另画场景、换画幅再出一版）是 `draw`，并把用到的图全部列进 media。
随后整跑发现新回归 D-008「我要一张极简风格的海报」被判 `ask`，又补了规则 4：
ask 只用于「画一下 / 帮我画 / 改一下」这类几乎没给内容的请求，给了题材/风格/尺寸就 `draw`。
两处都是独立提交（`fb35087`、`4fc24bc`），SAFE 三件套全过，之后才整跑全部 57 条。

最终唯一失分 **D-015「那两幅一起画成 Q 版」判成 `edit`**（参考图 2/2 正确）。
同一条事后连问 5 次，5 次都是 `draw`（3.1–12.5 秒），判定为主脑单次生成波动；
没有改 golden 标签，也没有为它再加规则。

### 7.3 延迟阈值

最终实测（有效样本 57 条）：p50 **1919ms**、p90 **3880ms**、max **4517ms**。
这是 core 模式下每条「被点名且含图/含画图词」消息**额外**的一次主脑调用，
不含最终出图耗时；最慢 4.5 秒低于生产 12 秒回退线。

**主人拍板（2026-11-06）：「延迟一般都没问题」** —— ⑤ 验收通过，**不另设数值阈值**
（不再追加「p90 ≤ X ms」这类非阻塞条件）。上面三个数只作为后续回归的对照基线；
若将来明显劣化再拿这份基线比较，不把它当成自动卡点。
