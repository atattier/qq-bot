## 7.5 WorkBuddy 外部大脑（值班巡检模式，2026-09-13 晚上线）

主人要的形态：**WorkBuddy 直接当小鲸的大脑**（像接了个 API），网页一键切回来。Qoder 大脑是"每条消息 spawn 一次 CLI"，WorkBuddy 没有无头入口学不了——所以反着装：**bot 闭嘴 + WorkBuddy 定时自动化长轮询巡群**。

- **切换**：/admin「大脑」下拉选 `workbuddy`（或群里管理员发「设置 大脑 workbuddy」）。`external_brain()`（bot.py）会同时闸掉三条自动发言路径（`ai_reply` 调用点 / `sim_allowed` / `idle_opener`），保证两个大脑绝不抢答；**切回 agent 全部恢复**。现画指令链路不受影响（不走大脑）。
- **长轮询**：`GET /api/wait_messages?after=<收件箱id>&timeout_sec=10..55`（提交 `b347e19`）——阻塞至多 55 秒，有新消息立刻返回 `{messages, last_id}`；服务器是 `ThreadingHTTPServer`，挂住不卡其他路由。MCP 侧第 10 个工具 `qq_wait_for_messages` 包装它（客户端 HTTP 超时 = 服务器 + 10 秒）。这是抄 qq-bridge 的解法：agent 在一个"等→处理→回→再等"循环里全天在线、空闲几乎不烧 token。
- **值班自动化**（WorkBuddy automation，id `8cc1ab3c-…`）：每小时触发（锚定创建时刻 20:58，实际约 :58/:02 分触发）。单班流程：`qq_status` 确认 brain=workbuddy（≠ 就静默收工）→ `qq_config` **现读人设**（主人面板改了自动跟）→ 读 `state/wb_poll.json` 拿游标 → 最多 65 轮 × 45 秒长轮询 ≈ 连续巡逻 50 分钟 → 有消息按纪律处理。纪律：@必回、每班 ≤12 条、每条 ≤30 字、绝不自称 AI/助手、`qq_config` 只读、画图指令 bot 本体自己接不归它管、游标**写不写得起都不挡发言**（防沙箱写文件受限卡死值班）。
- **值班人设**：跟 /admin「人格」区正文（config `ai.system`）一致，每班现读。当前文本 = Yuki《妹居物语》妹妹（温柔黏人、称呼哥哥、好感分档；面板档名「白圣」）。注意 `ai.role` 为空，`roles/*.md` 不参与。群聊只演"高好感常态"档，病娇/吃醋戏码不上桌。
- **额度**：自动化会话用 WorkBuddy 当前选中的模型，**不会自己挑免费档**——主人 22:47 已在该任务里把模型切到 hy3（限时免费）。空等阻塞不烧 token，每 45 秒醒来决策一次要烧；一班空跑 ≈ 2.3 万 token 量级。
- **兜底模式**：主人在场时说一声"巡逻"，本会话直接跑 `tools/_patrol.py` 循环（阻塞等待秒级响应），不开自动化不额外烧额度。
- **常驻脚本（推荐，绕开 WorkBuddy 不可靠的定时器）**：`patrol_bot.py` + `start_patrol.bat`。**双击 `start_patrol.bat` 即让小鲸 24h 自动值班**——进程常驻在你系统里，不依赖 WorkBuddy 会话、也不受命令回收影响（这是 WorkBuddy 自动化做不到的）。它直接打 bot 本地接口（`/api/status` 判 brain、`/api/wait_messages` 长轮询、`/api/send` 发群），用 config 里配好的 provider 逐条决策（默认 `zhipu_fast` 免费档，可在 `state/patrol.json` 换档 / 调轮询时长 / 每班上限 / 群号）。**只在 brain=workbuddy 时真发**，其余时间安静待命并推进游标防重复；被 @ 必回（硬兜底短句），灌水/两人聊天空转不接。纯标准库、零第三方依赖。`--once` / `--no-send` 用于调试（`--no-send` 干跑不真发）。
- **已知边界/坑**：① WorkBuddy 会话的 MCP 工具列表是**会话建立时的快照**——bot 侧重启后新增的 MCP 工具在老会话里调不到（兜底走 HTTP 直调）；② 自动化触发时刻锚定创建时间不是整点；③ 收件箱在 bot 内存里，**每次重启 bot 游标作废重收**（不会漏：NapCat 侧历史完好，重启后新消息从 1 重新计）。

## 7.6 好友私聊（单聊，2026-09-15 上线）

主人要求「**不止这一个群管用，也可以和好友聊天**」——即 bot 不只在群 123450001 响应，好友单独私聊它也能聊、能用全部口令。

- **核心设计 = 会话 key 抽象（务必先懂这个）**：全项目所有会话状态（`HISTORY` / `CONTEXT` / 收件箱 `INBOX` / 现画冷却 / 未读）都拿一个 `int` 当 key。私聊编码成**负数** —— `priv_key(uid) = -abs(int(uid))`：**群 = 正群号，私聊 = 负 QQ 号**。发送层 `send_group(cid)` / `send_segments(cid)` 是唯一碰 OneBot 俩接口的地方（`_api_send`），按正负自动选 `send_group_msg(group_id=…)` / `send_private_msg(user_id=…)`。**好处：既有整条口令链（形参就叫 `gid`）一行都不用改，群/私聊上下文天然隔离不串台**。
- **入口路由**：`dispatch(data)` 按 `message_type` 分派 —— `group` → `handle_group_message`，**`private` → `handle_private_message`**，两者都调共用的 `_handle_message(data, cid, is_group)`。`is_group=False` 时做三处例外：① `at_self=True`（私聊本身就是"在跟我说话"，不用 @）；② **不学黑话**（`maybe_slang_extract` 只在群里）；③ **不查违禁词、不仿真插话**（那是群语境）。
- **三层策略闸**（`config.private`，网页「私聊」卡可调）：
  - `enabled`（默认 **开**）总开关，关掉完全不理；
  - `strangers`（默认 **关**）非好友（`sub_type != "friend"`，如临时会话）也回 —— **默认关**，免陌生人骚扰；
  - `admin_only`（默认 **关**）只回白名单（`admin.owner_qq`）。
  **⇒ 好友默认就能聊；非好友默认不回；想只回白名单就开 `admin_only`。**
- **权限**：私聊没有"群角色"，`role` 一律按 `member` 算，所以**只有 `owner_qq` 名单里的人才算管理员**。改配置/管理命令的文案已从"群管理员权限"统一改成"管理员权限"（群私聊通用）。画图/反推仍吃各自卡里的「群友可用」开关，行为与群里一致。
- **主动发私聊的口子**：`_allowed_conv(cid)` = `is_priv(cid) or _allowed_group(cid)`（私聊不另拦，`bridge_token` 门已够）。`action_history` / `action_wait_messages` / `action_send` / `action_generate` 都走它，所以 MCP/值班可以主动给好友发私聊（传负数会话 key）。
- ⚠️ **真机 bug（上线当天踩到，务必记住）**：注入一条私聊，agent 大脑想完 ~20s 回了 `[SILENT]`（**群里的正常行为 = 潜水**），但**私聊里一潜水主人就对着空气**。两处修复：① `agent_system_text(gid)` 拆成**群/私聊两套**系统提示，私聊版明确写「**私聊必须回**：这是主人单独找你说话，不许回 [SILENT]、也不许把话憋着；没什么可说的就随口接一句」；② `ai_reply` 里 `[SILENT]` 的处理加 `is_priv` 分支 —— 群照旧 `return`（潜水正常），**私聊不 return、落回 API 大脑兜底**（日志打「(私聊里 agent 想潜水 → 回落 API 大脑，务必回一句)」）。
- **验证**：`tests/_tpriv.py`（**全打桩**，A–L 十二节：会话 key / 发送层分发 / 私聊进链 / 群私隔离 / 三层闸 / 权限 / 静默不影响私聊 / 口令 / 不当群用 / 群侧不回归 / `_allowed_conv` / **L 节：私聊 [SILENT] 必须回落、群潜水照旧**）。**⚠️ 打桩注意**：`build_messages` **不能打桩**（真实实现里它负责 `HISTORY.setdefault` + 记 user 轮，`ai_reply` 回落路径直接 `HISTORY[gid].append` 靠它灌种，打桩会假报 KeyError）。
- **真机复验手法**：事件入口是 `POST http://127.0.0.1:8088/`（非 `/api/`、非 `/notify` 的 POST 一律 `dispatch(data)`）—— POST 一个 `{"post_type":"message","message_type":"private","sub_type":"friend",…}` 的事件即可注入私聊；再用 `GET /api/history?group=-<uid>` 读线上会话记录核对机器人有无发出。实测主人私聊 → 机器人回到私聊（agent 主动 `qq_send` 发言）。
