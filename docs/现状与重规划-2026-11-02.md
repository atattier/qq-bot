# qq-bot 现状说明书（2026-11-02）

> 目的：把"它现在到底是什么"讲清楚——功能、架构、真实的问题在哪。
> 给重新规划做底。读这份之前不需要读代码。
> 数据全部来自当前代码实测（bot.py 19876 行 / 全项目 37056 行 / 48 个功能分节）。

---

## 一、一句话现状

**一个由 40+ 个互相独立的功能模块拼起来的 QQ 群机器人，靠"消息进来 → 一长串 if/正则/关键词链逐个尝试认领"驱动，AI 大脑只是这条链的末环。** 功能都能动，但它们不是被一个"大脑"统一调度的——这正是你觉得"臃肿、人机味重、不完美"的结构性原因。

## 二、现在一条消息是怎么被处理的（真实顺序）

群消息进来后，`handle_group_message` 里是这么走的（按代码顺序，命中即 return）：

```
① 硬闸层   「叫哥哥」闸 / 测试静音 / 白名单 / 出站审计
② 命令层   /mute /help /role /silent …（管理员斜杠命令）
③ 现画口令  「画：」「快画：」「/宫格」「moss反推」「moss改：」+ 30 多个画图变体正则
④ 口语改图  带图 + 改图动词（帽子低一点）→ moss 改稿
⑤ 带图点名  带图 + "图生图/云端/moss" → moss 反推重画（今晚刚加）
⑥ AI 路由  纯文本 → 让主大脑判断"是不是求画" → 是就排队
⑦ 视频生成  「生成视频」+ 素材记忆回捞
⑧ 视频解析  B站/抖音链接
⑨ 漫画      .jm 命令
⑩ 看图问答  @它+图 → 视觉模型回答
⑪ 看图闲聊  纯图无文字 → 按概率点评
⑫ 口语编辑  "帽子低一点"（非 moss-only 时）
⑬ 情绪/戳一戳/黑话学习/长期记忆写入
⑭ 最后才轮到 AI 大脑聊天（ai_reply）
```

**问题一眼可见**：所谓"大脑"排在第 14 位。前面 13 层全是关键词和正则——每层都在"猜"用户意图，猜错就吞掉或截胡（你截图里"图生图"被丢给大脑就是第⑤层新加的补丁刚好接住，之前是漏到大脑然后大脑乱来）。

## 四、真实的四个结构性问题

### 问题 1：意图路由是"正则瀑布"，不是"大脑决策"

现状：13 层前置闸门，每层自己的关键词表（画图正则、改图动词表、点名引擎表、口语编辑表……）。表和表之间有覆盖盲区（"图生图"不在改图表里），新加一层补一个洞，洞越补越多。**大脑只在所有表都没命中时才说话**——它其实是"兜底聊天员"而不是"总控"。

### 问题 2：工具面与口令面是两套平行系统

群里能干的事（画图/反推/查梗/记忆）有两条路：群口令（正则直通，快但死板）和大脑 function calling（灵活但大脑常常不知道该用哪个、或压根没挂）。两条路各自维护参数和话术，**同一件事两套逻辑**——截图里"画「生成一张图片，具体画面内容未指定」"就是大脑拿着画图工具自己编 prompt 的产物。

### 问题 3：人格（人味）与能力（工具）分离

人设正文（小柚.md）只管聊天口吻；工具调用全是机器人腔（"画「xxx」，大概 15~30 秒"是系统格式话术，不是人格在说话）。失败时大脑会装样子（"已经在弄了"）——因为人设里没有"工具失败必须坦白"的约束，模型默认演。

### 问题 4：240 个旋钮平铺，大多数没人动

旋钮体系（四入口同表）本身是好设计，但 240 项里高频动的不到 20 个。控制台重构已解决"看"的问题，但"少而精的开关 + 大脑自己判断细节"才是终局——很多参数（路由、引擎选择、补全勾选项）本该是大脑的判断，不该要人拨。

## 五、重新规划的思路（供讨论，不是定案）

核心一句话：**从"消息瀑布 + 兜底大脑"翻转为"大脑优先 + 口令兜底"**。

### 目标架构

```
消息进来
  │
  ├─ 硬闸层（保留：白名单/静默/审计/测试静音——这些不是"意图"，是安全）
  │
  ├─ ★ 大脑总控（新的第一决策者）
  │    · 一个统一的系统提示：你是谁（人格）+ 你有什么工具（全部能力面）
  │    · 大脑三种反应：
  │      a) 直接回话（聊天/提问/闲聊——人味在这里）
  │      b) 调一个工具（画图/反推/查梗/记忆/解析——参数由大脑填，话术由人格说）
  │      c) 明确说"这个我做不了"（禁止装样子——写进系统提示硬规则）
  │    · 快路径豁免：/斜杠管理命令、.jm 等明确前缀命令不过大脑（省 token 且确定性）
  │
  └─ 口令兜底（大脑挂了/超时的回落，现有正则表降级为应急通道）
```

### 关键改动点

1. **合并两套工具面**：把 13 层正则里的"能力"（画图/反推/改图/查梗/记忆查询）全部注册成大脑的 function calling 工具，删掉对应的正则直通（口令只保留管理命令和明确前缀）。
2. **人格写进系统提示**：现在人设只影响聊天文本；翻转载后它影响每一次工具调用的话术（"画好啦发这里～"而不是"已排队 #1"）和失败姿态（"这个我真画不出来"而不是"已经在弄了"）。
3. **诚实的失败**：系统提示加硬规则"工具失败时如实说失败原因，禁止声称在做"，配合现有 `_draw_err_hint`。
4. **旋钮瘦身**：240 项里给大脑的判断参数（路由模式、引擎选择）逐步退役成大脑自主决策；人只留权限/额度/密钥这类真正的"政策"项。
5. **速度兜底**：大脑优先意味着每条消息都过一次 LLM——用轻量模型（现有 modelscope 快档 1.8s）做总控判断，重的活（反推、生图）才升级调用。

### 风险与代价（诚实版）

- **每条消息都过大脑**：响应延迟从"口令即时"变成"1.8s+"；群闲聊也会烧 token（可用"非 @ 消息按现有活跃度规则决定要不要过大脑"折中）
- **回归风险大**：13 层正则各有踩坑史（HANDOVER 里全是事故记录），拆掉它们等于重写路由——需要分批：先合并画图/改图/反推三张表（本次截图暴露的），再逐步吞掉其它层
- **测试欠账**：_tset 有 3 条人格断言失败未修（HANDOVER §17），重构前必须先修好回归基建

### 建议的分批路线

| 批次 | 内容 | 效果 |
|---|---|---|
| A（小） | 人设加"诚实失败"硬规则 + 受理话术过人格口吻 | 立刻去一部分机器味，不动架构 |
| B（中） | 画图域试点：三张正则表（画图/改图/点名引擎）合并成大脑工具，带图消息全走大脑决策 | 验证"大脑优先"模式可行性 |
| C（大） | 全能力面注册 + 口令降级兜底 + 旋钮瘦身 | 完成架构翻转 |
| D（远） | 沙盒（控制台里测人格）、主动话题由大脑规划 | 人味持续提升 |

## 六、你现在要决定的

1. 认不认这个方向（大脑优先 + 口令兜底）？
2. 如果认：从批次 A 开始（今天就能做，零风险），还是直接规划批次 B？
3. 大脑模型档：总控用快档（1.8s，便宜，判断力一般）还是 custom（质量高但慢且贵）？这决定"大脑优先"的体验下限。
