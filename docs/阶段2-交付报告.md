## 2. 关键决策逻辑修改前后对比

| 环节 | 修改前（真实观察基线） | 修改后 |
|---|---|---|
| 工具调用次数 | 无上限（只受 8 轮 × 时间预算），实测单条 12 次搜索 | **硬预算**：默认 2 次；`_multi_step_intent` 命中明确多步骤话术时放到 6 次；超预算的调用**不执行**并回填"没做" |
| 重复调用 | 同一搜索换关键词反复搜 | 同工具同参数 → 复用上次结果不重执行；同工具**连续失败 2 次** → 第 3 次拒绝重试 |
| 画图多调 | draw_like_this 后又 cloud_draw（同请求出两张） | **画图单发**：draw_image/draw_like_this/cloud_draw 互斥，一个成功即拒绝后续 |
| 图片状态 | 大脑靠猜；无图仍调反推（17 次失败） | 系统提示注入**真实状态**：本条带图 N 张 / 引用消息有无 / 最近 10 分钟发过图；无图时明确"绝对不许调 reverse_prompt/draw_like_this" |
| 工具边界 | qq_groups"派活第一步先定位目标群"（导致闲聊也查群） | 每个工具 description 加**适用范围+禁止场景**；系统提示再列一遍硬规则 |
| 任务类型 | 改稿→查 6 个查询工具 | 提示词明确七类任务（查询/创作/改稿/生图/图编辑/回忆/聊天），改稿直接改 |
| 真实反馈 | 提示词已有原则，无代码强制 | 保留并加强；预算用尽的调用会回填"没有执行"，模型无法据此假装完成 |

## 3. 工具边界规则（实施后）

| 工具 | 允许调用 | 禁止调用 |
|---|---|---|
| `qq_groups` | 明确要求查看群列表/群号/群信息；派活需定位目标群 | 闲聊提到"群""你们"、吐槽、夸奖 |
| `qq_members` | 需要把昵称换 QQ 号（点名/私聊某人） | 为"了解一下"查成员表 |
| `qq_history` | 明确问"刚才谁说了什么"、派活需回忆上下文 | 普通聊天/讽刺/改稿/创作；反复翻记录找感觉 |
| `bot_status` | 明确问服务/显卡/队列/画图在不在跑 | "？""救活你""在吗" |
| `recall_memory` | 问"上次/之前/你还记得"、核实约定 | 改稿、创作、闲聊 |
| `web_search` | 需要外部时效信息；**一轮最多一次** | 换关键词反复搜同一件事 |
| `draw_image` | 明确要一张新图 | "来一张那种图""帮我画个"（无画面信息）→ 必须先追问 |
| `draw_like_this` / `reverse_prompt` | **本轮图片状态有图** | 无图（必须请用户先发图） |
| 全部工具 | 已有足够信息回答 → 立刻停 | 工具失败后换工具碰运气/反复重试 |

## 4. 图片上下文传递方案与证据

**方案（最小可靠改造）**：不走"提示词劝说"，在 `brain_with_tools` 构造 system 时用入口已有变量计算真实状态并注入：

```python
_n_this    = len([x for x in (imgs or ()) if x])      # 本条消息带图数
_has_quote = bool(qmid)                                # 是否引用了别的消息
_recent_img = (time.time() - _last_img_turn.get(gid)) < 600   # 最近 10 分钟发过图
# 无图时追加硬指令：绝对不许调 reverse_prompt / draw_like_this
```

**证据**：
- 日志实测（桩进程真跑）：`大脑决策[custom] type=chat img=0 quote=False cap=2`
- 真实模型回归 #9「反推一下」无图 → 工具=无，答复「反推得先有图啊兄弟，这条消息里啥图都没有」（旧基线：11 次无图反推失败）
- #11「照着刚才那张再画一遍」无图 → 工具=无，答复请用户重发图（旧基线：draw_like_this 6 次失败）
- #7/#8/#10 有图 → 正确调 draw_like_this / reverse_prompt 各 1 次

## 9. 典型成功与失败案例

**成功（修改后真实模型行为）**：
- 「画得挺像的」→ 无工具，回一句人话（旧：连调 5 个工具）
- 「窗外的天气～就像是～你多变的表情～」→ 无工具，接梗（旧：真画了一张）
- 「继续反推」无图 → 请用户发图（旧：reverse_prompt 失败）
- 「把这段改得不那么AI：今天天气很好…」→ 直接给三个改版（旧：6 个查询工具）
- 「去群里问问今晚谁在线，然后告诉我」→ 3 个工具串行完成（预算正确放宽到 6）

**仍存在的失败（如实记录）**：
- #18 多步骤里出现了 `qq_wait_new ×2`（第二次是继续等，属合理但接近预算上限）
- 一次真实调用的验证中，模型对"搜今天科技新闻"发了 **2 次不同关键词搜索**（预算内，但违反"一轮最多一次"的软规则）——提示词约束不是硬闸，后续可把搜索也纳入硬预算（当前未做，避免过度限制）
