# 工程规范（2026-11-05 U9 起）

本文件是约定速查，不是设计文档。设计决策与历史见 HANDOVER.md；审计依据见 docs/reports/。

## 异常处理

- **`except …: pass` 必须带一行理由注释**，且只允许两类场景：
  1. **清理/回滚尽力而为**（unlink、rmtree、进度通知失败不影响主流程）；
  2. **降级探测**（ capability 探测失败 = 没这个能力，静默回落）。
  2026-11-05 审计复核结论：既有 68 处静默吞异常全部属于这两类（清理型为主），
  未发现吞掉业务错误的案例；热点函数（_do_cover/_fetch_rev_image/_do_jm）逐一复核通过。
- 业务异常必须 log（warning 起步）并给用户可读话术；服务故障细节只进 log（meme 错误码分流是范本）。
- 裸 `except:`（不带类型）存量 347 处，新代码一律写明异常类型。

## 配置

- **config.json 单一可信来源 = config_core.CFG**。读：`from config_core import dot_get`；
  写改内存后调 `save_config()`（带锁+原子写，可并发调用）。
- 新模块**不许自己读写 config.json 文件**，也不许自己保存 CFG 引用快照（要活引用）。
- 新增配置段必须自带默认值兜底（`CFG.get("段", {}) or 默认`），并在 config.example.json 补键。
- 凭据（token/key）一律不进源码、不进文档；读 config.json 或环境变量（tools/show_qr.py 的
  `_read_secret` 是范本）。已进过 git 历史的值视为已泄，应轮换。

## 模块契约（bind 体系）

- 新功能模块：不 import bot；`bind(cfg=..., state_dir=..., logger=..., 回调...)` 注入；
  参数判空统一用 `is not None`（真值判断会把空容器回调静默忽略——U10 统一后的口径）。
- 模块级落盘文件（json/db）一律支持 `state_dir` 重定向，并在 **tests/_tisolation.py 的
  `_STATE_FILES` 登记**——忘了登记 SAFE 直接红（这是故意的）。
- 依赖注入两套风格并存是既定裁决：bind 体系（qbot_*）与散件传参（reverser/tts 等）各自保持。

## 摸头/捏脸双链路主备关系（2026-11-05 裁决）

- **qbot_meme（meme 服务 127.0.0.1:2233）为主**：`摸/摸头` 口令在 `_handle_message` 里先经
  `qbot_meme.handle`（bot.py 消息分发处），服务在线即接管（含 @人头像模式）。
- **qbot_petpet（本地 PIL 渲染）为备**：meme 总闸关闭或口令未命中时自然回落，捏脸能力不因
  meme 服务挂掉而丢失。
- 这是**有意保留的主备双实现**（服务挂了表情不断），不是重复垃圾——改动任一侧前先读本节。
