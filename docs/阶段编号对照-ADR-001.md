# 阶段编号对照（唯一口径：ADR-001 §7.3）

> 这份文件只做一件事：**不让任何一个会话再把 M4 说成 Memory Service**。
> 阶段编号的权威来源是 [`docs/架构决策-统一智能核心-2026-11-05.md`](架构决策-统一智能核心-2026-11-05.md)
> §7.3（ADR-001，冻结于 `810d62a`）。本文件是索引与纠错记录，不新增、不修改任何阶段。

## 1. 正式路线（照抄 ADR-001 §7.3）

| 编号 | 阶段 | 目标一句话 | 开关 |
|---|---|---|---|
| M0 | 基线 | golden set + 生产 diff 零 | tag `golden-m0-base-2026-11-05` |
| M1 | Turn + 影子核心 | 每条消息同时构造 Turn、影子判断，不发送 | `arch.shadow` |
| M2 | Context Assembler | 18 段统一上下文，逐段回退 | `arch.context=legacy` |
| M3 | Tool Registry | 3 套工具面 → 1 套契约，权限集中判定 | `arch.tools=legacy` |
| **M4** | **画图 / 视觉域切换** | 自然语言画图/反推/改图由核心判断；多图与跨轮指代可用 | `arch.draw=legacy` |
| **M5** | **Memory Service / Persona / Renderer** | 统一记忆读写与投影；人格进 Assembler/Renderer；发送唯一出口 | `arch.memory=legacy` / `arch.render=legacy` |
| M6 | 退役与清理 | 删已退役的路由/死代码/旧表/旧前端 | 单批 revert |

**红线**：

1. **M4 只指画图 / 视觉域。** 任何人（包括 agent 会话）把 M4 说成 Memory Service、
   人格、渲染、工具执行权接管，都是错的，按本表纠正。
2. **Memory Service / Persona / Renderer 是 M5。** 记忆字段级对账、投影重建、
   人格进 Assembler/Renderer、发送唯一出口，全部属于 M5。
3. 阶段编号与验收条件**只能引用 ADR-001 §7.3 的原文**；不得在会话里自创编号或验收口径。
4. 实施中发现必须改编号/验收的阻塞性问题：先修订 ADR（ADR §7.4），不要在下游文档里绕开。

## 3. 未排期事项（不在 M0–M6 编号内）

以下工作真实存在，但 ADR-001 没有给它们阶段编号，文档里不许硬塞进 M4/M5：

- 聊天/主动插话路径收进核心（`_route_brain_reply` / `_route_group_ambient`）。
- 工具执行权真正接管（Registry 从 shadow 变 executor）、`ToolResult` 全量替换、审计轮转。
- 「多图条件生成」（M4 只做到合成图垫片，见 M4 报告 §4）。

排期时由主人拍板是并入 M5/M6，还是另开 ADR。
