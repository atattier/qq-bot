# 人味阶段 B · 时机层实施与验收（2026-11-04）

对应研究文档 `docs/人味阶段研究-2026-11-03.md` 第 1 节（MaiBot 时机机制）与第 4.2 节。
一句话：**以前是「过了所有闸就判一次」，现在是「过了所有闸再算一下这批值不值得花一次 LLM」**，
并且连续没话说会自己退避、热闹了自动绕过、模型可以主动说「先等一等」。

🔴 **总闸 `timing.enabled` 默认关**：关着的时候本模块在所有入口恒放行、恒不记账，
提示词与旧版逐字节一致 —— 行为零变化。主人确认观察后再开。

## 一、四个机制 → 代码映射

| # | 机制 | 代码 | 行为 |
|---|------|------|------|
| B4 | 概率门 `reply_likelihood` | `qbot_timing.reply_likelihood()` | 纯函数：权重表原值移植（截距 −1.2005、提名字 +1.5852、@别人 −1.1157、问句 +0.4807、纯图 −1.0281、近期自发言占比 +2.6525、条数/间隔/积压项）→ sigmoid 概率。特征全来自廉价本地数据，**不花 token** |
| B4 | 自校准 `dynamic_gate` | `qbot_timing._evaluate()` | 1 小时滑窗：实际开口数 vs Σ概率×话痨系数。说多了门槛 +0.05（封 0.9）；说少了每次 −0.02 **但永不低于静态门槛**（校准只能更谨慎，不能比主人设的基线更话痨）；窗口样本 <20 条直接用静态门槛 |
| B5 | 指数退避 + 积压绕过 | `qbot_timing.should_judge/note_silent/note_reply` | 连续 [SILENT] 第 n 次（n≥2）→ 退避窗 15s×2^(n−2)，封 `backoff_cap`；**一批攒够 `bypass_pending` 条直接绕过**（热闹来了别装死）；任何回复/@/点名立即清零 |
| B6 | [WAIT:秒] 等待出口 | `qbot_timing.parse_wait/set_wait/wait_remaining` + `sim_join`/`_sim_batch_flush` | 模型可只输出 `[WAIT:N]` 表示「先等一等」；flush 发现 wait 未到点 → 本批塞回合批窗滚动，到点或被 @/点名/回复唤醒再判。wait 不消耗冷却/配额 |
| B6 | 开场退避 | `qbot_timing.opener_gap_multiplier/note_opener` | 冷场开场被 [SILENT] → 下次尝试间隔 ×2 递增（封 4 倍）；开场成功清零 |

接线点（`bot.py`）：
- `_sim_batch_flush`：`_sim_should_judge` 之后、拼 prompt 之前过时机门；wait 未到点则原样塞回窗口
- `sim_join`：提示词条件追加 `[WAIT:秒]` 选项（仅总闸开且 `wait_max>0`）；输出先解析 WAIT，再判 SILENT/正文；开口成功记 `note_reply`
- `_handle_message`：`addressed` 为真时记 `note_reply`（被点名立刻醒，try 包裹不影响回复链）
- `idle_opener_tick`：间隔乘开场退避倍率；提示词补「可回复对象」与 [SILENT] 逃生；开场结果记账

## 二、新增旋钮（群「设置」/ 网页「群友 → 时机」）

| 旋钮 | key | 默认 | 说明 |
|------|-----|------|------|
| 时机门 | `timing.enabled` | **关** | 总闸。关=下文所有机制都不生效 |
| 概率门槛 | `timing.likelihood_min` | 0.35 | 静态门槛；自校准只会在它之上收紧 |
| 话痨系数 | `timing.talk_value` | 1.0 | 自校准目标倍率（>1 更活跃，<1 更收敛） |
| 退避封顶 | `timing.backoff_cap` | 300 | 指数退避最长秒数 |
| 积压绕过 | `timing.bypass_pending` | 6 | 一批攒够这么多条无视退避 |
| 等待上限 | `timing.wait_max` | 180 | `[WAIT:N]` 上限；0=不给模型这个选项 |
| 开场退避 | `timing.opener_backoff` | 开 | 冷场开场 [SILENT] 后间隔翻倍（封 4×） |

开启方式：群里发「设置 时机门 开」，或 /console → 行为开关 → 时机。改完立即生效（hot）。

## 三、红线与边界（逐条对照）

1. **mood 仍是唯一权威**：心情/冷却/每小时配额/密度闸全部在时机门**之前**一票否决；
   时机门只决定「已经过闸的这批值不值得再花一次 LLM」。`sim_bias` 只作为概率特征输入。
2. **addressed 必答路径零改动**：@/名字/口令/私聊/画图即时路径完全不经过本模块；
   只是额外记一次 `note_reply`（关闸时 no-op）。
3. **发送闸不动**：`sim_allowed` / `sim_note_sent` / 限速 / 熔断一行未改；wait 不调 `sim_note_sent`。
4. **关闸=旧行为**：概率门恒放行（理由「时机层未启用」）、不记账、不解析 WAIT、提示词不追加任何字符。

## 五、设计取舍（如实记录）

1. **wait 怎么「等」**：不另开长定时器，而是把本批原样塞回**现有**合批窗口滚动（沿用 6s Timer），
   到点或被唤醒再判 —— 研究文档 §4.1 明确警告过长期 tick 堆积的坑。测试态合批窗被强制 0，
   所以测试里临时关 `_IN_TEST` 拿真窗口；生产路径始终有窗。
   （中途踩坑：初版 flush 用裸 `CFG["batch"]` 取窗、和 `batch_push` 的 `_batch_cfg()` 不同源，
   测试态会同步递归炸栈 —— 已改为同源取窗，并在 `_ttiming` 里加了源码级守卫。）
2. **静态门槛 0.35 与普通陈述**：按权重表，普通陈述的概率约 0.347，**恰好卡在默认门槛下**；
   问句约 0.46、被提名字更高。也就是说开闸后「纯陈述」默认不进 LLM 判定，
   要把门槛调到 0.3 以下才会全放 —— 这是有意为之：先不判，等话头。
3. **自校准「说少了」是缓退**：每次只 −0.02，连算几轮才贴回静态，避免一天没说话就把门槛砸到底。
4. **真机抽查模型三次都选了 [SILENT]**：说明 WAIT 是选项不是义务；「什么时候真会选 WAIT」
   要在真实群聊里观察，别用一次性验收下结论。

## 六、观察指南（开闸后）

- 启动日志：`时机门关/开`（每次重启都打，先确认开关状态）
- `grep 时机不判`：被概率门拦下的批次和原因（含概率与门槛，自校准会标「（自校准）」）
- `grep 时机额度自校准`：门槛变动与 1 小时「预计/实际」开口数
- `grep 时机退避中`：退避拦下的批（连续几次没话说、还要等几秒）
- `grep 时机等待`：模型选了 `[WAIT:N]`；`grep 时机等待.*唤醒` 暂无（唤醒走 note_reply 静默清零，看下一条判定即可）
- 判断效果：同一天内「合批 N 条 -> 一次判定」的次数应下降，但被点名/问句的响应率不应下降。
  连续两天觉得它变闷 → 先把「概率门槛」降到 0.3 或「话痨系数」调到 1.3 再观察。
