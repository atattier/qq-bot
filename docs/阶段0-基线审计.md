### 静态发现（重构靶点）
- **单函数 1900 行**，41 个 return 分支；分支间靠 `text` 变量被沿途改写（前缀剥离）耦合。
- **语义重叠三处**：①`handle_settings` 与 8 个配置正则（16976-16998）是两套同功能入口；②画图口令正则（16800 段）与 `_ai_route_draw`（LLM 判断）是两种路由模式靠 `draw.route` 开关二选一；③`_looks_like_edit` 与 `_MENG_EXPLICIT_RE` 同为带图意图判断，词表独立演化（"图生图"漏网的直接原因）。
- **带图消息永不过 AI 路由**（17303 显式排除 `not pic_imgs`）——设计注释说"改图/看图有专用分支，别截胡"，但专用分支词表不全时消息会漏进 ai_reply 且丢失画图意图。

### 技能工具（qbot_skill_tools.py TOOLS）
按包分组：`fibi-memes / memewiki / petpet / trendy-memes / whale-memes`（MCP 暴露）。

### 关键发现
1. **大脑工具与口令已经收敛到同一实现**（draw_submit/handle_i2i/handle_moss_draw）——提案 §3.4"复用现有模块"在画图域已部分成立，重构的量比预想小。
2. **资源闸已存在**：`_TOOL_CTX allow_draw`（5693）——大脑没被@时禁止画（"这条没人点你名，先别画"）；搜索有同轮去重闸。提案 §3.3 调度层的两个样板已在。
3. **schema 与口令参数不对齐处**：`draw_image` 无 `edit`（补全要求）、无 `reverse_mode`（hybrid）、无 `detail`（详细程度）——这三个参数只有口令链/网页工具有。**工具面落后于口令面**。
4. `omni_brain` 总控开关默认 False（零回归保守），当前主人配置 custom 大脑 + 工具面已接（function calling 实测可用）。

## 阶段 0 结论

1. **画图域具备试点条件**：大脑工具与口令已共享 `draw_submit` 等底层实现；缺的是①工具 schema 补齐（edit/hybrid/detail 三参数）②话术人格化③意图测试集跑起来。
2. **最大的非技术风险**已确认：_tset 回归带伤（3 条失败）——阶段 1 开工前必须先修。
3. **最小试点路径**（供阶段 1 评审）：不动路由瀑布，先给 `draw_image` 工具补齐 `edit/brief/detail/hybrid` schema → 大脑画图能力与口令对齐 → 用测试集 10 例做人工对照评分。
4. 配置治理与人格表达层按提案 §6/§5 单独立项，不在阶段 0 范围。
